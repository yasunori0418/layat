# CASE-a9ff732c-af30-4f13-862d-92e3074d390d: niface_payload_test.go — engine 結果からペイロードへの写像

## 対象

`cmd/layat/niface_payload_test.go`

## 検証内容

- **インベントリと change の写像** — item が新 manifest の entry と stale 除去された旧 entry の
  全数になること、差分のある遷移だけが change になること、状態の変わらない再 link が change を
  作らないこと、配置方式の変更（symlink → copy）が 1 item + 1 change へ束ねられること
- **配置系の change の可逆性** — symlink の張り替えは復元先を伴う可逆な変更になり、copy の
  上書きは復元先を持たない不可逆な変更になること（撤去ではなく変更として現れる点を含む）
- **dryrun での非抑制** — 実行結果と違い計画では再 link を抑制しないこと
- **到達状態のパーティション** — 完了 / 失敗（分類コードつき）/ 未到達の skip が区別されること
- **エラー層の置き場所** — entry スコープの失敗を subject の errors へ重複させないこと、
  主体起因の失敗はそこに 1 件だけ載ること、conflict がその一種として扱われること
- **warning の振り分け** — インベントリに存在する対象の警告は item へ載ること。配置系では
  孤児・保守的に残した stale がインベントリの外にあるため、その警告は subject へ載ること
  （撤去系では同じ種類の警告が item 側に載る。下の撤去系の項を参照）。警告種別からコードへの
  対応が全種別で成立し、未知の種別がフォールバックすること。警告と error の同居でも適合を
  保つこと
- **世代スロット** — 変更前後の世代を持つこと（初回は変更前を省略、失敗時は動かない）、
  世代の概念を持たない実行ではスロット自体が不在であること、profile 未作成の dryrun で前後
  ともに省略されること
- **ロールバックの遷移方向** — 世代を戻す実行では前後が後退する向きの遷移として現れること、
  失敗して戻せなかったときは動かなかった現行世代として前後が同値に観測されること
- **撤去系の写像と可逆性** — 撤去の対象が item の全数になること、symlink の撤去は記録済みの
  復元先を伴う可逆な変更になり、copy の削除は復元先を持たない不可逆な変更になること（削除が
  捨てるのは記録済みの配置元ではなくディスク上の内容であるため）、保守的に残した対象は成功の
  まま変更を作らないこと（方針としての不作為は差分ではない）、その対象への警告は撤去対象の
  インベントリに含まれる以上 item 側へ載ること（配置系で subject 側へ載るのと対になる）、
  撤去系は世代を動かさないためスロット自体が不在であること
- **撤去系の到達状態** — 途中まで撤去した分は変更として残り、失敗した対象は分類済みの誤りを
  持ち、着手されなかった残りは skip になること
- **終了コードと文書の併存** — 計画時の conflict では、conflict を示す終了コードとともに
  エンベロープが欠けずに出ること
- **`info` の非出力** — 変更系がエンベロープにも結果にも `info` キーを出さないこと
- **実 engine を通した経路** — 一時ディレクトリ上で実際にコミットまで走らせ、同じ写像が
  成立すること

適合チェッカを併用しつつ、主眼は schema では縛れない**内容**の検証にある。
