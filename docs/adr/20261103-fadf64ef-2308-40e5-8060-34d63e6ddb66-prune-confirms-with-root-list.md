# ADR-fadf64ef-2308-40e5-8060-34d63e6ddb66: prune は削除前に root パスの一覧を示して確認を取る

- ステータス: 採用
- 日付: 2026-11-03
- 関連: ADR-acc31876-df36-485e-b356-92ae60e26db7, GitHub Issue #580
- 起点: 次期マイルストーン計画の grilling（2026-07-04）。公開後の実運用で孤児系列が溜まり始めたことを消費側の要求と判断した。ADR-0034 §2a を書き直した

## 背景

root の実在で孤児を判定する方法には、誤判定する場合が 1 つある。
リムーバブルディスクやネットワークマウント上のプロジェクトは、アンマウントしている間は root
が一時的に実在しないように見える。この状態で prune を実行すると、
生きている系列を孤児と誤って判定する。

## 決定

prune は、実際に削除する前に削除対象の root パスの一覧を必ず示し、reset
と同じ形の確認を取る（ADR-acc31876-df36-485e-b356-92ae60e26db7）。`--dryrun`
は削除予定の系列を出力するだけで、何も削除しない。
マウントポイントの判定のような機械的な区別は行わず、アンマウント中の誤判定がありうることは docs
に注記する。

確認の省略（`--yes`）、非 TTY での扱い、`--dryrun` の出力の規範は
REQ-42fe312c-927c-4da3-9346-f7ca2f3a58ed に置く。

## 根拠

アンマウント中かどうかは、root パスを見た利用者ならすぐ分かるが、機械には確実に判定できない。
一覧を見せて人の判断を挟むのが、この誤判定を最も安く防ぐ方法になる。

確認の形を reset と揃えると、削除系のコマンドで覚える操作が 1 通りで済む。

## 棄却した代替案

### マウントポイントを調べて、一時的な不在を見分ける

automount・ネットワーク FS・FUSE など、マウントの形態ごとに判定が変わり、確実には見分けられない。
見分け損ねたときの害は誤削除で、確認を取るより安全にはならない。

### 確認を取らず、事前の確認は `--dryrun` に任せる

アンマウントに気付かないまま実行した利用者を守れない。
