# TC-b0e0cdb8-0c56-4eb8-8d4e-86569af85dec: 破壊的操作の確認が対話性と同意フラグの組み合わせで決まり非対話で止まらない

## 条件

確認プロンプトを出すか、出さずに進むか、出さずに拒否するかが、対話性・同意フラグ・機械可読
出力の指定の組み合わせで決まることを確かめる。

- 同意フラグがあれば、対話・非対話を問わずプロンプトを出さずに進む
- 対話環境で同意フラグが無ければプロンプトを出す
- 非対話環境で同意フラグが無ければ、入力待ちで止まらず即座に拒否する
- 機械可読出力の指定はプロンプトを常に禁じるため、同意フラグが無ければ先へ進まない

入力の解釈も条件に含む。肯定と読むのは明示的な肯定入力だけで、空行・未知の入力・入力の終端は
いずれも否定として扱う。既定を否定側に置くのは、確認が意味を持つのは取り違えが破壊につながる
場面だからである。

対話性の判定そのものは、パイプやリダイレクトされた入力に対して非対話と判定されることを
確かめる。端末に接続されている側の判定は自動テストの実行環境では作れないため、この条件の
検証範囲外に置く。
