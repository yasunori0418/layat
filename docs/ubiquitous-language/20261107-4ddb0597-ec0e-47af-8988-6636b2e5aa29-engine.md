# UBQ-4ddb0597-ec0e-47af-8988-6636b2e5aa29: engine

## Definition

The placement core that owns both placement (native filesystem operations) and stale removal. It takes `manifest.json` as input, invokes only `git` (toplevel) as an external command, and is implemented as a Go library driven by the **layat CLI**. It leaves recording and switching generations to the **generation backend**. It does not generate a bash script per config. "Library" here means internal in-binary layering under `internal/`, not a publicly importable, reusable module — the stable surface is the `manifest.json` contract. The engine is stdlib-only.

## Avoid

"per-config generated bash script", "per-layer placement logic", "a single flat implementation fused with the CLI", "importing the engine as a public Go module".

## 定義

配置（ネイティブなファイルシステム操作）と古くなった配置の除去の両方を一手に所有する配置コア。`manifest.json` を入力に取り、外部コマンドは `git`（toplevel）のみを叩く。世代の記録・切替は **generation backend（世代バックエンド）** に委ねる。**layat CLI** が駆動する Go ライブラリとして実装される。config ごとに bash スクリプトを生成しない。ここでの「ライブラリ」は `internal/` 配下のバイナリ内部の層分離を指し、公開 import 可能な再利用モジュールではない——安定面は `manifest.json` 契約に閉じる。エンジンは stdlib-only。

## 避ける表現

「config ごとに生成される bash スクリプト」「層ごとの配置ロジック」「CLI と一体の平らな単一実装」「engine を公開 Go モジュールとして import する」。
