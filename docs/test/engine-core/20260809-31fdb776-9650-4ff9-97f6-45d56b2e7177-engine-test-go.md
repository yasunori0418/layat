# CASE-31fdb776-9650-4ff9-97f6-45d56b2e7177: engine_test.go

## 対象

`internal/engine/engine_test.go`

nix を介さず実 FS（`t.TempDir()`）へ apply を回す統合テスト。link farm と manifest を
テスト側で組み立て、配置結果を実 FS のプローブで確認する。

`resolveRoot` を直接叩くテストだけは例外で、分岐網羅を 1 ファイルで追えるよう
generations_test.go 側からもここへ集約した（→ issue #328）。多くは純引数だが、cwd を
入力に取る経路（相対パスの絶対化）は実ディレクトリへ `t.Chdir` して期待値を定める。
cwd を壊して `os.Getwd` を失敗させる固定 root の Abs 失敗のみ、FS 誘発型として後段の
セクションに残る。

## 主な検証内容

- **初回配置と subpath**: project mode の初回配置、`subpath = "."` の配置
- **配置分類**: 自己記録 symlink の無警告張替え、foreign symlink の警告付き後勝ち
- **上書き拒否**: target の通常ファイル占有でエラー停止、祖先 symlink でエラー停止、
  祖先が自己記録 stale のときのみ移行（copy 子を含む）
- **stale 除去との接続**: 記録済み entry の除去、foreign を残すこと
- **root 解決**: `rootKind=home` が `$HOME`、`rootKind=system` が `/` を返すこと、`--root` 上書きが rootKind に
  よらず優先されること（system・未決（`""`）・未知の値と組んでも拒否されず override の絶対パスが
  返る）、相対 override が cwd 起点で絶対化されて返ること、git repo 外でのエラー、
  固定絶対 root の解決失敗、`fixed` でパスを省いた
  ときの拒否（エラー本文一致。manifest 層が受理する組み合わせを engine が止める責務
  → CASE-4179dcb2-f199-4469-ae87-0927ece06e65 / TC-172548ea-154a-4e22-a169-8252a43e3781）、rootKind 未決（`""`）と未知の値の拒否（いずれも
  エラー本文一致。未知の値は `%q` のクォートまで含めて固定する）、profile ディレクトリ作成失敗・backref 書き込み失敗の
  エラー化
- **out-of-store**: live symlink の配置、stale 除去、リンク先不一致時の保持、marker の
  リンク先が不在のときのエラー停止（dangling symlink を作らず target も残さないこと）
- **root 相対**: target のディレクトリを起点にした相対リンクとして配置され、配置 root の下の
  実体へ解決されること。entry を足した別の世代で再 apply しても警告無しでリンクが変わらない
  こと、entry を外した世代で stale として除去されること
- **copy 経路の呼び出し**: place-once の初回・既存保持、foreign 実ファイルの skip 警告、
  ディレクトリ再帰コピーでの内部 symlink 保存、`--recopy` の上書き（foreign 含む）
- **conflict 報告**: 複数 conflict の全件列挙と件数を含む集約エラー、dryrun と本番 apply が
  同数の conflict を報告すること、
  自己矛盾する祖先・copy 構造不一致それぞれのガイダンス、種類混在時のガイダンス対応付け
- **system mode**（TC-be3d3dc9-1ead-4e2e-8eea-46e1c8884562）: euid 0 以外を注入した apply が
  `fs.ErrPermission` を wrap したエラーで止まり、root・profile 基底・記録基底に何も作らないこと、
  同じ注入の dryrun は通ること。`Geteuid` 未設定の非 root 実行もプロセスの euid で同じく止まること
  （root 実行では skip）。euid 0 を注入し `--root` を tmp に向けた apply が system 基底の
  `<roothash>/<name>` に profile と backref を作り、`SystemDir` が `Backend.SystemBase` より優先され、
  ユーザー state に何も作らないこと
- **その他**: `--no-wait` で lock 取得済みのときの skip、pending 除去失敗の警告化
