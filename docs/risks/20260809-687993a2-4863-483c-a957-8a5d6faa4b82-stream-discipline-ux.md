# RISK-687993a2-4863-483c-a957-8a5d6faa4b82: stdout の所有権と確認プロンプトの規律が崩れパイプ利用と非対話実行が壊れる

## リスク

stdout は機械可読出力が専有し、人間向けのレポートと warning は stderr へ出す、という分離が
崩れると、パイプへ流した出力に人間向けの行が混入して消費側のパーサが壊れる。とくに `--json`
指定時は行指向の出力が全て止まらなければならず、コマンドを 1 つ足したときにその停止を配線し
忘れるのが典型的な壊れ方である。逆に、stderr へ出すべき通知まで止めてしまうと、人間が実行
したときに何が起きたのか分からなくなる。

破壊的操作の確認プロンプトは別の壊れ方をする。非対話環境（パイプ・CI）で同意が得られないまま
プロンプトを出すと、応答の来ない入力待ちで停止する。逆に非対話であることを理由に確認を
省いて実行に進むと、同意なく破壊的操作が走る。どちらも「即座にエラーで止まる」という規律から
外れた結果として起きる。`--json` は常にプロンプトを禁じる側へ倒れるため、明示的な同意フラグが
無ければ先へ進んではならない。

成功時のデフォルト沈黙も同じ系統にある。成功したときに余計な出力を出すと、スクリプトから
使う側が出力の有無で成否を判断できなくなる。

## 影響

パイプ利用時のパース破壊と、非対話実行時のハングまたは無同意実行。impact を high とするのは、
プロンプト側の壊れ方がユーザー環境の破壊に届くため。非対話であることを理由に確認を省いて
進めば、同意なく `reset` の teardown が走る。同意を欠いたまま正常に走る teardown が消すのは
layat 管理下の配置物だが、そこには copy target が含まれる。copy は世代管理の対象外なので
ロールバックでも再実行でも戻らず、失われるのはユーザーが配置後に編集した内容そのものになる
（→ RISK-01cf9f47-95bd-419a-863d-0d7c1f8188ba）。除去範囲そのものが逸脱して管理外の実体まで消す側は RISK-bb54245e-b284-4b4d-9896-8fec2b4e521c の
担当で、同意ゲートについても engine 層は同 item が扱う。あちらの「緩和」節が cli-json 区分へ
委ねた TTY 判定と `--yes` の解釈の側を本 item が持つ。ストリーム側の壊れ方
（パースエラー・入力待ちでの停止）は配線を直した再実行で回復するが、規約の最重方向則に従い
最も重い方向で採る。

likelihood を medium とするのは、ストリームの所有権は TC-b4a365cd-0b1c-40ff-92c6-91f6cffe8e98 が、同意ゲートは
TC-b0e0cdb8-0c56-4eb8-8d4e-86569af85dec が対話性・同意フラグ・機械可読出力の組み合わせで覆っている一方、コマンドを
1 つ足したときに `--json` 時の行指向出力の停止を配線し忘れる経路が残るため。加えて
TC-b0e0cdb8-0c56-4eb8-8d4e-86569af85dec は端末に接続されている側の対話性判定を「自動テストの実行環境では作れない」
として検証範囲外に置いており、そこは残余になる。
