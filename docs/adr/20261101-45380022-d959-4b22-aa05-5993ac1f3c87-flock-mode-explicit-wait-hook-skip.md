# ADR-45380022-d959-4b22-aa05-5993ac1f3c87: flock は明示実行で待ち、hook 実行でスキップする

- ステータス: 採用
- 日付: 2026-11-01
- 関連: ADR-0021, ADR-0022, ADR-0031
- 起点: engine の設計と実行時セマンティクスの確定（2026-06-11〜06-13）。ADR-0006 §「決定」の並行実行・ADR-0013 §2 を書き直した

## 背景

同じ profile への適用が並行すると、配置と世代のコミットが競合する。そのため engine は profile ごとに
ロックを取る。ロックを他のプロセスが持っているときの振る舞いには、相反する 2 つの要求がある。

- ユーザーが明示的に実行した apply は、確実に適用されてほしい。スキップされると、適用済みだと誤解する
- devShell の shellHook はシェルに入るたびに apply を起動する。高い頻度で実行されるので、待ち行列を作ると
  シェルに入るまで待たされる

## 決定

profileDir のロックを取る apply / rollback / reset について、ロックの取り方を起動元で分ける。明示的に
実行したときは、ロックを取れるまで待つ。shellHook から `--no-wait` 付きで起動した apply は、ロックを
取れなければ配置をスキップし、シェルへの入室を止めずに終える。

フラグと待機中の表示は REQ-1c1526b1-59e3-4264-bb7c-65a10a4aa461、スキップ時の通知を `-v` なしでは出さないことは
REQ-8ef34101-8150-4124-92d5-94fabe6b5d90、reset のロックは REQ-a8edc58f-4adc-4637-b888-ab8ccc7e73e4 に置く。

## 根拠

明示実行と shellHook では求めるものが違うので、起動元で分ければ両方を満たせる。どちらから起動されたかは
テンプレートが shellHook に埋めるフラグで判別するので、engine が呼び出し元を推測しなくて済む。

shellHook がスキップしても、ロックを持っている側の適用はそのまま進む。適用は冪等なので、スキップした
分は次の適用で同じ状態に収束させられる。

## 棄却した代替案

### どの起動元でもスキップする

明示的な apply もスキップされ、利用者が適用済みだと誤解する。

### どの起動元でも待つ

shellHook が高い頻度で待ち行列を作り、devShell に入るまで待たされる。

### 短く待ってから、取れなければスキップする

明示的な apply でも、待ち時間を超えればスキップになる。確実に適用したいという要求を満たせない。
