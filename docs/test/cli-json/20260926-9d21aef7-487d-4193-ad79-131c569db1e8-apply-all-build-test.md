# CASE-9d21aef7-487d-4193-ad79-131c569db1e8: apply_all_build_test.go — 並列 build の並列度上限・失敗集約・--jobs の値域・--debug prefix・集約の同一性

## 対象

`cmd/layat/apply_all_build_test.go`

## 検証内容

- **並列度の上限** — build 関数を注入し、in-flight 数を数えるバリアで min(`--jobs`, config 数)
  に到達すること・超えないことを `--jobs` 1 / 3 / 16 で確かめる
- **stage 1 失敗の短絡** — 失敗する build を注入し、stage 2 の apply 関数がその config で
  呼ばれないこと、subject が選択順に並び失敗 config が error で載ること、stderr に
  `layat: apply <name> failed:` が出ること。`--dryrun` の集約でも同じく短絡され exit 1 に
  なること
- **集約の同一性** — 失敗・skip を混ぜた同じ入力を、build の完了順が辞書順の逆になる遅延を
  付けて `--jobs 1` と `--jobs 8` で流し、件数・stage 2 の辞書順呼び出し・エンベロープの
  バイト列が一致すること
- **`--jobs` の値域** — 解決関数の負値エラー・0 → `runtime.NumCPU()`・正値そのまま。apply
  コマンドを実際に実行し、`--all` 無しの `--jobs`（明示の 0 を含む）が modifier エラーに
  なること、ローカルフラグで既定 0・persistent でないこと。偽の nix を PATH 先頭に置き、
  `--all --jobs -1` が nix を 1 回も呼ばずに止まること
- **stage-1 の配線** — 同じ偽 nix（build は全て失敗）で `apply --all` を `--debug` 付きで
  `--dryrun` の有無の両方について駆動し、stage 1 の build 開示行が
  `[<name>] layat: + nix build ` で始まり一括 eval の開示行は prefix 無しであること、build が
  config ごとに 1 回の `--no-link` realize だけで失敗 config が stage 2 で再 build されないこと、
  nix の stderr が失敗 config の報告の中にだけ config ごとに 1 回現れること
