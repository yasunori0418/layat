# ADR-2f5b8825-f13b-4f73-bdf1-fe14e0098d57: リポジトリ全体は subpath の省略で表す

- ステータス: 採用
- 日付: 2026-11-03
- 関連: `docs/spec.md`, `CONTEXT.md`
- 起点: 「リポジトリ全体を示す文字列として `"."` 以外の表現は無いか」という問いの設計検討。ADR-0008 §3 と §4 を書き直した

## 背景

配置元の中のパスを `subpath` と呼ぶと決めたあとも、リポジトリ全体を配置するときの書き方が残る。
候補は `subpath = "."`、`null` や `""` のような専用のトークン、全体を表すマーカー（`wholeRepo`）、
`subpath` の省略だった。layat のマーカーは、評価時にパスへ展開できないもの（`$HOME` や git の
toplevel）の種別を運び、実行時に解決させるための入れ物である。

## 決定

リポジトリ全体は `subpath` を省略して表す。`subpath = "."` も全体を明示する形として合法に残し、
専用のトークンや全体を表すマーカーは設けない。型と既定値は
REQ-27b75fe6-6c36-44a8-8cd3-5cc98043022a に置く。

## 根拠

サブパスを指定しなければ全体、という読み方は語として自然で、新しい語彙を覚えさせずに済む。
`subpath` は store パスの中のパスを選ぶもので、store パスは評価時に分かっているから、`subpath` は
評価時に完全に確定する。全体を表すマーカーを作っても評価時に `"."` へ畳まれるだけの糖衣になり、
実行時に解決する種別を運ぶというマーカーの定義と食い違う。

## 棄却した代替案

### 全体を表すマーカー `wholeRepo` を設ける

評価時に `"."` へ畳まれるだけの糖衣で、初めての糖衣マーカーになる。root や out-of-store の
マーカーで確立した「実行時解決の種別を運ぶ」という意味がぶれる。

### `null` や `""` を全体の正規の表現にする

省略で表せるのに別のトークンを足すことになる。`""` は typo を誘い、パスを連結したときの意味も
曖昧になる。
