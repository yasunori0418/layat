# INF-0865477b-21b2-4feb-9c06-1a882a4e595a: ドキュメントサイト（Astro Starlight + Cloudflare Pages・ビルド時リファレンス生成）

## 構成

Astro（Starlight）のサイトを **同一リポジトリの `site/`** に置く。別リポジトリへは分離しない。
リファレンスの抽出元（`lib/` の doc-comment・Go ソース）とサイトが同じリポジトリにあることで、
API 変更とドキュメント更新が同一 PR で原子的に進む。

載せる内容は **usage ガイド + API リファレンス（英日）**。設計根拠のドキュメント（ADR /
`CONTEXT.md` / `docs/spec.md` / `docs/design.md`・日本語）はリポジトリ内に留め、サイトには
載せない。

## ホスティングとデプロイ

- ホスティングは **Cloudflare Pages**。PR ごとの branch deploy でドキュメントレビューを URL で
  回せる
- デプロイは Cloudflare の Git 連携ビルドではなく **GitHub Actions から wrangler で行う**。
  ビルドに nix（nixdoc / gomarkdoc の実行）が要り、Cloudflare 側のビルド環境では賄えないため。
  main への push で本番デプロイ、PR で preview デプロイ
- **ビルド検証**は CI パイプライン（INF-d1230e1f-8ba8-49d8-8386-409bfbb7dd27）の check 群へ加え、リファレンス抽出の破損
  （doc-comment の構文エラー等）をマージ前に検出する。**デプロイ**はそれとは別の workflow で
  行い、main への push と PR で本番 / preview を打ち分ける

## リファレンスの生成

生成 markdown は**リポジトリにコミットしない**。CI / ローカルのビルドステップで毎回生成し、
ソースとリファレンスの乖離を構造的に排除する。

| ソース | 抽出 | 対象 |
|---|---|---|
| Nix lib | nixdoc | 公開 API（`mkManifest` / `mkOutOfStoreSymlink` / マーカー群）の RFC-145 形式 doc-comment（`/** */`） |
| Go | gomarkdoc | godoc コメント。主対象は CLI（`cmd/layat` のコマンド体系）。`internal/` は公開 import 面ではないため掲載範囲は実装時に絞る |
| 手書き usage ガイド | — | `site/` 配下に英日で執筆 |

Nix lib のコメントは役割で使い分ける — `/** */` が公開 API 契約、`#` 行コメントが実装注記。

## i18n

Starlight の i18n で **root ロケール = 英語（`/`）、日本語 = `/ja/`**。README を英語 canonical と
した公開方針と一貫させる。未翻訳ページは標準機構で英語へフォールバックし、日本語訳の遅れが
リンク切れにならない。用語は `docs/glossary.md`（英語 canonical）/ `docs/glossary.ja.md` に準拠する。
