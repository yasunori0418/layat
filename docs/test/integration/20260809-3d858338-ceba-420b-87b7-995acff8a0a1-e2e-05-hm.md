# CASE-3d858338-ceba-420b-87b7-995acff8a0a1: e2e 05-hm — 非 NixOS で HM configuration を実際に activate する

## 対象

`tests/e2e/scenarios/05-hm.sh`

## 検証内容

- 公開された home-manager モジュールを外部の fixture flake から import した configuration を
  組み、activation package をビルドして実際に activate すること
- activate の結果として、隔離した HOME の配下に store の配置物が現れ、内容が配置元と一致する
  こと（評価アサートの CASE に対する実行時の対）
- `layat.entries`（`default` の糖衣）と別名の config を併せ持つ configuration を activate すると、
  両方の配置物が現れ、2 つの profile が状態ディレクトリ配下にそれぞれ独立した世代を 1 つずつ持ち、
  別の store パスを指すこと
- 2 つの config が同一の target を持つ configuration は評価とビルドを通り、activate は非ゼロで
  終わり、出力に target と両 config 名が載り、target も両 profile も作られないこと
- 辞書順で後の config の target を外来の実ファイルで塞いだ configuration では、activate は
  非ゼロで終わり、前の config は配置されて世代をコミットし、塞がれた側は外来ファイルを保ったまま
  世代をコミットしないこと
- subdir を与えた config を activate すると、配置物が隔離した HOME の `<subdir>/` 配下に store の
  配置物として現れ、内容が配置元と一致し、その profile が世代を 1 つ持つこと
- 絶対パスの subdir を与えた configuration は activation package の build が非ゼロで終わり、
  診断に `root subdir` が載ること
- 公開ラッパーが CLI の注入を含んでおり、利用者側が追加の記述なしに consume できること
- 主体が確立した後に評価が失敗する実行で、失敗が subject 側の errors に構造化され、item は
  空のまま、終了コードが一般エラーになり、文書が適合を保つこと
- 同じ評価の失敗で、実 nix 自身の診断（属性が無い旨）が stderr へ届き、`--json` の
  `errors[].message` にも同じ診断が含まれること

standalone の home-manager が実行ユーザー名と一致する設定を要求するため、実ユーザー名を
取得して configuration を組む。依存は lock の pin へ追従させてオフラインで評価する。
