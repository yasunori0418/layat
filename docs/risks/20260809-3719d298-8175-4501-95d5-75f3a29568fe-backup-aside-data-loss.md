# RISK-3719d298-8175-4501-95d5-75f3a29568fe: --backup の rename 退避がユーザーの実データを上書き・喪失させる

## リスク

`apply --backup` は conflict の脱出ハッチとして、配置を塞ぐ記録外実体を
`<target>.<suffix>` へ rename 退避する。退避対象は定義上「layat が記録していない実データ」
であり、扱いを誤れば直接ユーザーのファイルを失わせる。

失われ方は 3 つある。

1. **退避先の黙った上書き** — `<target>.<suffix>` が既存（前回の退避の残り）のとき、
   conflict で停止せず rename してしまうと、前回退避した実データが消える
2. **plan / execute 間の TOCTOU** — plan 時点で退避先が不在でも、execute 時点で他プロセスが
   そこにファイルを作っていることがある。rename 直前に再検証しなければ、その並行生成物を
   黙って潰す（→ ADR-0017 の再検証原則）
3. **退避が commit 後に消える** — `--recopy` の rename 退避は成功時に discardJournal が
   掃除するが、`--backup` の退避はユーザーのバックアップであり永久に残す契約である
   （→ ADR-0045・`reset` も復元しない）。掃除の対象を取り違えると、ユーザーが唯一の
   コピーだと思っていたものが消える

逆方向の欠陥も本リスクに含む。`--backup` 無しの既定で conflict のまま停止するはずの
ケースが退避へ流れると、ユーザーが opt-in していない破壊的操作が既定で走ることになる。
世代スキップ（drift 修復）経路で Backup 段だけは到達し続けるという段の位置付け
（→ REQ-9b0046e0-8ddc-4c0b-940e-3fe6f36d0e98）が崩れる場合も、退避されるべき実体が conflict のまま放置されるか、
逆に修復経路で予期しない退避が起きるかのどちらかになる。

## 実現性

**likelihood: medium** — 退避は opt-in であり既定経路では走らない。ただし発火条件
（記録外実体が target を塞ぐ）は foreign tool による書き換えで日常的に成立する。

**impact: high** — 対象が定義上「layat の管理外にあるユーザーの実データ」なので、
喪失は復旧不能。
