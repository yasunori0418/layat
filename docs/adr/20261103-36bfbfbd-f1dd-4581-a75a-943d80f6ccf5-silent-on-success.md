# ADR-36bfbfbd-f1dd-4581-a75a-943d80f6ccf5: 成功時は既定で何も出力しない

- ステータス: 採用
- 日付: 2026-11-03
- 起点: ADR-0031 §1・§4 を書き直した

## 背景

以前の CLI は、`apply` / `reset` / `rollback` が成功すると配置レポート（サマリと target ごとの行）を
既定で stderr に出し、`--quiet` で抑えていた。成功はいちばん多い結果で、shellHook から呼ぶと入室の
たびにレポートが流れる。静かにしたい呼び出し側（shellHook・スクリプト・CI）は一律に `--quiet` を
付けることになり、既定で出したうえで呼び出し側ごとに抑えるという、本来とは逆の形になっていた。

## 決定

`apply` / `reset` / `rollback` が成功したとき、配置レポート・skip の通知・`--all` の完了サマリ・
「対象 config なし」の通知を既定では出さない。warning と error は常に stderr に出す。既定が沈黙なので
`--quiet` は持たない。

沈黙の対象と対象外（warning / error・`reset` の確認プロンプト）は
REQ-8ef34101-8150-4124-92d5-94fabe6b5d90 に、`--quiet` を提供しないことは
REQ-0a123b89-0399-4f76-b988-56a5f7e0becf に置く。

## 根拠

成功は終了コード 0 で伝わる。成功時に何も出さなければ、目に入るのは失敗と警告だけになる。shellHook も
フラグを足さずに静かになる。

既定で何も出さないなら、`--quiet` には抑える出力が無い。残しても何もしないフラグになり、既定で
何かが出るという誤解を招く。

## 棄却した代替案

### 既定でレポートを出し、`--quiet` を残す

以前の形で、静かにしたい呼び出し側がフラグを付け続けることになる。

### `--quiet` を受理して無視する

既存の呼び出しはそのまま動くが、意味の無いフラグが残り、既定で出力があるかのように読める。廃止した
時点の利用者は限られており、互換を保つ利点は小さい。
