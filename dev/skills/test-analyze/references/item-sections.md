# test-analyze 工程の item 本文の節構成

frontmatter は `sara init` が生成する（手順は sara-docs の references/sara-cli.md、
フィールドの正本は `docs/model.yaml`）。ここは test_condition item の本文
（Markdown 部分）の節構成を定める。

## test_condition item（`docs/test/` 配下・区分はプロジェクト規約）

```markdown
# <検証テーマの短い名前>

<リード文: 何を検証する条件か。「どんな入力・状況でどう振る舞うべきか」の
 抽象レベルで 1〜2 段落。期待結果の具体値・検証手段は書かない>

## 切り口とテストベース

- 切り口: <機能要求 / 入力の区分 / 状態・遷移 / 例外・エラー処理 / 非機能 / 相互作用・依存>
- テストベース: <対応する REQ / DSG の省略形参照（REQ-xxxxxxxx）・コード箇所・受け入れ条件>

## 備考（test-design への引き継ぎ）

<任意。識別中に出た細分化した入力区分・境界値・期待値の素材。テスト条件としては
 1 件に畳んだが、ケース導出時に使う情報をここへ残す。無ければ節ごと省く>
```

- 対応する risk は frontmatter の `mitigates` が正本なので、本文に「対応リスク」節は
  持たない（二重管理になる）。リード文で言及したいときは省略形参照で書く。
- **優先度の節は原則持たない**。優先度は `mitigates` 先 risk の `level` から導出する
  （複数なら最高 level）。導出と違う扱いをする例外のときだけ、根拠と利用者決定を
  リード文または備考に書く。
- name（frontmatter）は「〜こと」で終わる検証可能な言明にすると、条件か設計かの
  区別が付きやすい（例: 「target 不在時のみマテリアライズし、既存 target を触らないこと」）。
