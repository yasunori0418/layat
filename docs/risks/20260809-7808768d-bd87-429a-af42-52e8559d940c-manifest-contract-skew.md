# RISK-7808768d-bd87-429a-af42-52e8559d940c: Nix と engine の唯一の契約である manifest の生成側と消費側がずれる

## リスク

`manifest.json` は Nix 側の評価と Go 側の engine をつなぐ唯一の安定契約であり、両側が同じ
文書を同じ意味で読めることに全体が乗っている。ここがずれると、評価は成功しビルドも通るのに
配置の段で意味を取り違える、という発見の遅い壊れ方をする。

ずれ方は 2 方向ある。

- **バージョンの skew** — 利用者が pin した flake（生成側）と手元の CLI（消費側）の版が
  食い違い、消費側の知らない版の文書が渡る。このとき「壊れた JSON」ではなく「読めるが意味の
  違う文書」として通ってしまうと、ずれに気づく機会が失われる。移行機構を持たない方針を
  採っている以上、拒否そのものが契約の一部であり、しかも原因が skew だと分かる形で拒否
  できなければ利用者は対処できない
- **契約の暗黙拡張** — 消費側が未知のフィールドを黙って無視すると、生成側が足したつもりの
  情報が届かないまま実行が進む。届いていないことに誰も気づかない

root の種別ごとの扱いも同じ場所にある。評価時に絶対パスが決まる種別と、実行時に解決する種別が
あり、この区別を取り違えると配置先そのものが変わる。本 item はこの区別を消費側が受理の段で
守ること（→ REQ-dd10d820-e453-4099-a47a-ffb9a7de02fb）を射程に含む。生成側が同じ区別で文書を組み立てる側は
RISK-5df2d02b-e5d4-40eb-86ad-e8bc96e4c34d の担当で、同じ requirement を別の facet から脅かす。

## 影響

意図しない場所への配置、あるいは原因の分からない失敗。impact を high とするのは、root の種別を
取り違えた受理が配置先そのものを変え、書き込み先が layat の記録に残らないため。どこへ撒いたかを
辿れない以上、契約を直して再 apply しても撒いた側は回収されない。ずれが「読めるが意味の違う
文書」として黙って通り、統合層すべての土台であるこの契約を通じて layat のどの利用経路にも波及
することは、その回収に着手する契機まで奪う。

likelihood を low に留めるのは、本 item の射程が消費側の受理
（版の拒否・未知フィールドの拒否・root の種別が空である文書の拒否・実行時に解決する種別が
パスを併記した文書の拒否）と統合層の配線に限られ、前者は Go の契約テスト（TC-172548ea-154a-4e22-a169-8252a43e3781）が、
後者は activation が root と entry とオプションを engine へ届けることの評価アサート
（TC-5a72b00e-2c03-4703-acdc-33cffb6fa994）が覆っているため。評価層が文書の形を変えてしまう側は本 item ではなく
RISK-5df2d02b-e5d4-40eb-86ad-e8bc96e4c34d の担当で、そちらはフィールド追加・既定値変更という通常の改修で動くぶん
likelihood が一段高い。

消費側の受理が見るのは root の種別が空でないことと、実行時に解決する種別がパスを併記して
いないこと（→ REQ-dd10d820-e453-4099-a47a-ffb9a7de02fb）までで、種別が既知の 4 値のいずれかであることは見ていない。
そちらは engine の root 解決が未知の種別を弾いて止まるため、黙って通る経路にはならない。
