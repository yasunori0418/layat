# ADR-509e15a2-9097-404d-bc3c-171fe63dd3c8: クラッシュ耐性のための永続 WAL を持たない

- ステータス: 採用
- 日付: 2026-11-03
- 関連: ADR-74423bb8-1453-4689-a25e-30bf46536afc, ADR-3aebefee-405d-4342-b754-eef8eac29b1b, ADR-56325270-20bb-4959-8498-e3223c35e24b, GitHub Issue #168, #172
- 起点: 旧 epic #167 から統合された epic #172 の grilling セッション（2026-07-11・2026-07-12）で確定。ADR-0044 §4 を書き直した

## 背景

undo ジャーナル（ADR-56325270-20bb-4959-8498-e3223c35e24b）は、プロセスが error を返せる
失敗を巻き戻す。SIGKILL や電源断、回収されない panic でプロセスが終わると、メモリ上の
ジャーナルも失われる。この場合まで保証するかを決める必要があった。

## 決定

ジャーナルはプロセスのメモリ上にだけ置き、ディスクへ永続化しない。クラッシュで終わった run は
巻き戻さない。クラッシュ後の保証は、世代を未コミットのまま残すことと、冪等な再実行で FS が
収束すること（ADR-74423bb8-1453-4689-a25e-30bf46536afc）が担う。

張替えの間にクラッシュしたときの扱いは REQ-61856da1-8883-401e-ad57-9f326b96d400 に置く。

## 根拠

error を返したときの巻き戻しとクラッシュ耐性は別の保証である。前者は、apply が失敗を自分で
報告できた場合を全て適用前の状態へ戻す。後者には永続 WAL、fsync の規律、クラッシュ後の
回復手順が要る。

クラッシュの場合は、世代が進まず、同じ manifest の再適用で FS が収束する。symlink の張替えも
2 操作の間のクラッシュを再実行で収束させている（ADR-3aebefee-405d-4342-b754-eef8eac29b1b）。
この下支えで運用できているので、ジャーナルはその上に「プロセスが生きている間の失敗は
すぐ元に戻す」という品質を足すだけにとどめる。

## 棄却した代替案

### ディスク上に undo ログ（永続 WAL）を持つ

クラッシュまで含めて巻き戻せるが、fsync の規律・回復手順・WAL 自体が壊れたときの扱いが要る。
途中失敗を元に戻すという目的に対して、実装と保守のコストが大きすぎる。
