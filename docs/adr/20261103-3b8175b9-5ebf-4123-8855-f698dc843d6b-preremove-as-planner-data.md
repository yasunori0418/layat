# ADR-3b8175b9-5ebf-4123-8855-f698dc843d6b: 配置前除去を planner が計算するデータとして表す

- ステータス: 採用
- 日付: 2026-11-03
- 関連: ADR-74423bb8-1453-4689-a25e-30bf46536afc, ADR-dfe6654c-8fcd-4cf6-a053-c21ad6dc373c, GitHub Issue #170, #175, #172
- 起点: dotfiles 側での実遭遇（#170）と grilling セッション（2026-07-11・2026-07-12）で確定。ADR-0046 §3（配置前除去のデータ化と実行順）と ADR-0047 §4 を書き直した

## 背景

apply の本流は、新しいものを先に置き、古いものを最後に消す
（ADR-74423bb8-1453-4689-a25e-30bf46536afc）。自己記録の古くなったものが配置を塞ぐとき
（ADR-dfe6654c-8fcd-4cf6-a053-c21ad6dc373c など）は、それを配置の前に消さなければ置けない。
この順序の例外をどこで決め、どう表すかを決める必要があった。除去には symlink の unlink の
ほか、実ディレクトリの target を移行するときの空ディレクトリの rmdir もある。

## 決定

配置の前に除去するものは、planner が計算して plan の配置前除去の列に載せる。engine はそれを
配置前除去、配置、copy の反映、古くなった配置の除去の順に実行する。列の要素は除去の種類（unlink か rmdir）を
持ち、実行順は列の順で表す。planner は子を親より先に積み、同じ target は 1 件にまとめる。
後段の古くなった配置の除去は、配置前除去に載った target を飛ばす。

plan の構造と planner・engine の分担は DSG-8b96869c-842e-4f78-8ff7-df1f1d6c1a68 に、段の並びは
REQ-9b0046e0-8ddc-4c0b-940e-3fe6f36d0e98 に置く。

## 根拠

順序の決定を純粋な planner に閉じれば、例外を含めた plan をテストで確かめられる。dryrun と
apply が同じ plan を共有するので、予告と実際の除去も一致する。本流の順序はそのまま残り、
例外は前段に明示した局所的なものにとどまる。

除去の種類を要素の型に持たせると、entry を伴わない空ディレクトリの rmdir も同じ列で表せる。
engine は種類で分岐するだけで済み、順序を推論しなくてよい。

## 棄却した代替案

### engine の側で順序を暗黙に決める、または全体の順序を反転する

純粋な planner の外に順序の判断が出て、新しいものを先に置く本流も崩れる。

### 先に全て消してから全て置く（home-manager と同じ完全な二段化）

依存の無い独立した古くなった配置の除去まで前段に移る。除去の後・配置の前にクラッシュすると、新旧
どちらのパスにも実体が無い瞬間が生じる。依存する除去だけを前段に出せば、この瞬間は生じない。

### 移行のパターンごとに個別の特例を足す

祖先の symlink、実ディレクトリの target、method の変更と、パターンが増えるたびに例外が積み
重なり、保守できなくなる。
