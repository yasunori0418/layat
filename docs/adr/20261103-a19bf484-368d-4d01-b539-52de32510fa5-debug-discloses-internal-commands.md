# ADR-a19bf484-368d-4d01-b539-52de32510fa5: 内部コマンドの開示を --debug に分ける

- ステータス: 採用
- 日付: 2026-11-03
- 起点: ADR-0031 §3 を書き直した

## 背景

以前の `--verbose` は、CLI が内部で実行する nix コマンドを逐次開示するフラグだった。一方で
`--verbose` に求められていたのは配置の結果を詳しく見ることで、結果の詳しさとトラブルシュートの
ための開示という別の目的が 1 つのフラグに載っていた。

## 決定

内部で実行するコマンドの開示は `--debug` を付けたときだけ行う。`--debug` は `-v` と独立した
フラグにする。

`-v` と `--debug` の分担は REQ-0a123b89-0399-4f76-b988-56a5f7e0becf に置く。

## 根拠

配置の結果を見たい利用者と、評価や build の失敗を追いたい利用者は別の情報を求める。フラグを分ければ、
レポートだけ欲しいときに内部コマンドの列を浴びずに済み、内部コマンドだけ見たいときにレポートを
出さずに済む。`--help` の透明性の説明も、内部コマンドの見方として `--debug` を案内すればよい。

## 棄却した代替案

### `-v` に内部コマンドの開示も残す

フラグは 1 つで済むが、レポートだけ欲しい運用でも内部コマンドまで出る。

### `-v` を多段にし `-vv` で内部コマンドを開示する

段数で表すと、目的の違う 2 つを同じ軸の強弱として扱うことになり、何段目で何が出るかが読み取り
にくい。独立したフラグのほうが意味が明快である。
