# 品質（`quality`）

* [リリースはバージョンの一次情報の変更で駆動し、手作業の工程を挟まない](./20260808-0949183b-7ef0-4cae-b88f-3ad361576b63-release-driven-by-source-of-truth.md) - バージョンは flake の `version` と Go バイナリに埋め込む文字列の両方が述べるが、それぞれを手で書き換える運用は片方だけが古くなる。一次情報を 1 箇所に置き、他はそこから導出する。
* [リファレンスドキュメントは記述対象のソースから生成し、生成物を持たない](./20260808-0d42104c-a3c2-4bd1-9cad-a42d9e5a56a1-reference-docs-generated-from-source.md) - 記述対象を変えたのに記述を直し忘れる、というずれ方は「気づいた人が直す」運用では検出できない。ソースの doc-comment から毎回生成し、生成物をコミットしないことで、乖離が起こり得る状態そのものを作らない。
* [最新 main のビルド成果物を再ビルドなしに消費できる状態を保つ](./20260808-58522afb-31d5-4a1f-a7df-0858efa9e44b-prebuilt-artifact-availability.md) - layat は flake input として消費されるツールであり、消費側の CI やローカル環境が layat を使うたびにソースからビルドするのは実用上のコストになる。最新 main の成果物を公開キャッシュから取得できる状態を保つ。
* [ドキュメントグラフのトレーサビリティは機械的に検証する](./20260808-6bf957d9-17d9-4660-92b7-ebd6eeb71a8c-document-graph-mechanically-verified.md) - 文書間の参照が指す先を失う、というずれ方は「気づいた人が直す」運用では検出できない。存在しない ID への参照・ID の重複・循環は、人が読んで気づく類の誤りではないため、機械検証に置く。
* [マージ前の自動検証を必須にし、プラットフォーム差が効く層は全プラットフォームで通す](./20260808-a5f7f088-a459-4bb2-9674-82b1a4a52053-cross-platform-verification-before-merge.md) - layat は複数の OS / system で動くことを主張するツールであり、その主張は「手元の 1 環境で通った」では裏づけられない。マージ前の自動検証を必須にし、プラットフォーム差が影響する層は全プラットフォームで通す。
* [設計判断は ADR に記録し、改訂の書き戻しと item への接続を同じ変更の中で完了させる](./20260809-030f926b-5ae7-4543-b8cb-e66aae5e2b5e-adr-decisions-recorded-and-connected.md) - 決定を記録しない、あるいは記録したが後続の改訂で一部だけが古くなった ADR を有効なまま残す状態は、その ADR だけを読んだ人に「上書きされた内容」を最新仕様と誤読させる。本 item はその防止を規範として固定する。
* [用語の正名は用語 item が固定し、執筆はそれに従う](./20260809-4a623664-650d-4a08-800f-691f4ea6ff91-glossary-fixes-canonical-terms.md) - 同じ概念が箇所ごとに違う語で呼ばれると、読み手は同じものを指しているのか判断できず、検索も当たらなくなる。正名を 1 箇所で固定し、執筆はそこに従う。
* [公開ドキュメントは英語を canonical とし、日本語版を対で保守する](./20260809-5ecd74ba-889a-4e06-b32b-e67f10a45051-public-docs-english-canonical.md) - 公開されたリポジトリの読者は日本語話者に限らない。利用者に向けた面は英語を canonical に置き、日本語版はその対として保守する。どちらが原本かを固定しないと、片方だけ更新されたときにどちらが正しいかを読者が判断できなくなる。
* [規範は 1 ファイル 1 item のグラフが持ち、概要文書は索引に縮退させる](./20260809-67715bb3-1162-4ccf-8441-2f44257a57da-normative-items-placement-and-authoring.md) - 規範を概要文書と item の両方に書くと二重管理になり、改訂で片方だけが古くなる。規範の所在をグラフ側に一本化し、概要文書は通読の起点としての索引に徹する。この分担は文書の分量ではなく**どちらを正とするか**の宣言であり、概要文書へ仕様を書き足すことは規範の複製にあたる。
* [欠陥はトラッカーが持ちドキュメントグラフは規範のみを持つ。起票は分類語彙を経由する](./20260809-87b7776a-9ece-42ac-9a56-78daacb42217-defects-in-tracker-graph-holds-norms.md) - グラフが持つのは「そうあるべき姿」であり、欠陥は「起きた出来事」になる。両者を同じ場所に置くと、規範の集合に時系列の記録が紛れ、規範だけを読みたい参照が汚れる。所在をトラッカーとグラフで分ける。
* [傾向の計測は報告に留め、マージの条件にしない](./20260809-8c6767e4-dddb-48fb-b010-d363a936e746-measurement-reports-without-gating.md) - QA-a5f7f088-a459-4bb2-9674-82b1a4a52053 が「マージ前の自動検証を必須にする」側を規範化するのに対し、本 item は**必須化しない側の境界**を定める。両方が無いと、必須化の規範が「検証と名の付くものはすべて塞ぐ」と読めてしまう。
* [完成の定義は単一の機械パース可能な文書で持ち、項目数を上限で縛る](./20260809-9b5ccfce-25c2-4a90-977f-711ca489e9f4-dod-single-machine-parsable-document.md) - 完成の定義が複数箇所に散ると、どれを満たせば完成なのかが読み手ごとに変わる。単一の文書を固定パスに置き、そこだけを見れば判定できる状態を保つ。
* [コード整形と静的解析を自動検証に載せ、同じ判定を手元でも得られるようにする](./20260809-a92341b9-c873-406e-8b70-a64f56d8a7d6-formatting-and-static-analysis-automated.md) - 整形の揺れと静的解析が見つける類の誤りは、レビューで指摘できるが指摘に人の注意を払わせるだけの価値が無い。マージ前の自動検証の側へ回して、人のレビューを意味判断に集中させる。
* [自動化が取り込む実行物は不変な識別子で固定し、権限は最小に絞り、不正入力では成果物を作る前に失敗する](./20260809-d028e302-8262-428c-9030-98d46b4b0cd3-automation-supply-chain-safety.md) - CI と自動化は、このリポジトリの変更なしに振る舞いが変わり得る面を 3 つ持つ。外部から取り込む実行物・与えた権限・受け取る入力である。3 つとも、問題が起きたときに影響が及ぶ先が「マージ前の検証」と「リリースされる成果物」なので、規範として固定する。
