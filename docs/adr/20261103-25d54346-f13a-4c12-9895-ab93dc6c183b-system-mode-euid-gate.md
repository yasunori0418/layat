# ADR-25d54346-f13a-4c12-9895-ab93dc6c183b: system mode の変更系操作の前に engine が euid 0 を検査する

- ステータス: 採用
- 日付: 2026-11-03
- 関連: ADR-0036
- 起点: 次期マイルストーン計画の grilling（2026-07-04）。ADR-0036 §2 を書き直した

## 背景

system mode は root = `/` に配置し、profile も system 基底に置くので、root 権限が無ければ書き込みは
必ず失敗する。検査をしなければ、失敗は flock の取得や一部の検査が進んだあとで、最初に触った target の
`EACCES` として現れる。どの target で失敗するかは偶然に左右され、sudo での再実行を促す案内も無い。

## 決定

system mode の config に対する変更系の操作（`apply` / `reset` / `rollback`）では、engine がディレクトリの
作成や flock の取得より前に実効ユーザー ID が 0 であることを検査し、0 でなければ root 権限での再実行を
案内するエラーで停止する。読み取りだけの操作（`list-generations`・`apply --dryrun`）は検査しない。

検査の対象とエラーの扱いは REQ-0d1f557b-7ae7-41ea-b17b-cdb5c80935d4 に置く。

## 根拠

前段で検査すれば、権限不足による失敗が決定的になり、エラーも原因を直接示せる。検査を CLI ではなく
engine に置くのは、NixOS / nix-darwin モジュールの activation から `apply --manifest` で起動する経路も
同じ検査を通るようにするためである。

見るのは実効ユーザー ID だけで、sudo・doas・root でのログインを区別しない。`SUDO_USER` などの
環境変数に頼ると、起動のしかたによって結果が変わる。

読み取りだけの操作を検査から外すのは、非 root の利用者でも計画の確認と世代の閲覧ができるようにするため
である。eval と build は nix daemon を通すので、非 root でも実行できる。

## 棄却した代替案

### 検査をせず、書き込みの失敗をそのまま返す

失敗が最初に触った target の `EACCES` という偶然の形になり、sudo での再実行への案内も無い。
前段で止める方が、利用者にとってもテストにとっても扱いやすい。

### 検査を CLI に置く

モジュールの activation のように CLI の外側の入口から engine を呼ぶ経路が増えたとき、検査を通らない
経路ができる。
