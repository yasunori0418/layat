# TC-4e0a14d6-342c-448b-964b-b8e87520e89b: info スロットと世代スロットが値の無いときキーごと不在になり空配列は保つ

## 条件

省略されるべきフィールドが、ゼロ値として出力に現れないことを確かめる。この条件が独立して
必要なのは、`{}` や `null` や `""` を含む文書も schema 上は合法であり、適合チェッカでは
検出されないため。ここはテストでしか守れない層である。

確かめる境界は 2 つある。

- **不在であるべきとき、キーごと消える** — 列挙に到達せず失敗した読み取り系では `info` が
  キーごと現れない（値の struct をそのまま出すと `{"paths":null}` のような文書になる）。
  変更系は `info` の席を持たないので、エンベロープにも結果にも `info` キーが現れない。
  世代の概念を持たない実行と、profile が未作成で世代番号を持たない dryrun では、世代の
  スロットが 0 や null として現れない
- **0 件であるべきとき、空配列が残る** — 列挙して 0 件だった読み取り系は `[]` をキーごと
  残す。nil スライスがそのまま消えると「列挙していない」と「列挙して 0 件だった」が
  区別できなくなる

不在と 0 件は消費側にとって別の意味であり、この 2 つが同じ出力になる事態を避けたい。

> スロットが在るか無いかはこの条件の担当で、在るときの前後の値が正しいかは [engine 結果から item と change への写像がインベントリ全数と実差分に一致する](engine-result-inventory-mapping.md) の
> 担当。
