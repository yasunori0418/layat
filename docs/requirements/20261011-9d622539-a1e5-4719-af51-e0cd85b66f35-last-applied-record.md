# REQ-9d622539-a1e5-4719-af51-e0cd85b66f35: apply は最後に配置した manifest を last-applied 記録に書き、stale 除去の baseline は記録を優先して読む

## 仕様

- **置き場と鍵**: `<state>/layat/<鍵>/last-applied.json`。鍵は profileDir と同じ規則
  （home は `<name>` 直、他は `<roothash>/<name>` + backref `.root`）。
- **内容**: `recordVersion` / `linkFarm` / `appliedAt` / `manifest`（verbatim）。manifest を
  内容ごと持つので、記録の有効性は store の GC と無関係。
- **書き込み**: 全 FS 操作の成功直後・世代 commit の前に atomic に書く。記録は「この root に
  layat が最後に置いたもの」という FS の事実であり、commit の成否と独立。書けなければ操作は
  失敗し undo journal が FS を巻き戻す。
- **更新する経路**: apply（generation skip を含む）・rollback 成功後（N-1 の manifest）・
  reset 成功後（撤去 entry を除いた manifest。全撤去でファイル削除）。
- **baseline の優先順位**: 記録 → nix profile の current → 空。不一致は記録を採り warning
  1 行。どちらも無ければ初回として「last-applied 記録なし」を stderr に 1 行。対象は apply の
  stale 除去、drift / generation skip の link-farm 比較、reset の撤去対象、rollback の
  baseline（N）。rollback の target（N-1）は世代リンクから読む。

変えないもの: `--json` の契約・flock の鍵（profileDir）・prune の対象。記録のレイアウトは
DSG-3c156bbe-e72b-43dd-8cb0-2cc105314ad5、stale 除去の保守的不変条件は
REQ-16aef46b-7bb8-4ca1-b962-e9f3ed1fd1d2、rollback の手順は
REQ-0e341430-17f0-498b-9439-65491652163a の担当。

## 出典

ADR-0058「last-applied 記録」§1〜§4。
