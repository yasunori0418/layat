# SDR-4656dd7b-0ea4-48fb-a6c4-a8c96ad50103: 省略形の禁止は起票の機械化と全面移行で担保する

- ステータス: stable
- 日付: 2026-11-01
- 関連: SDR-722ce265-2aaf-4a90-915d-32d26b7a38bb, GitHub Issue #366, #364
- 起点: epic #364 の着手前 grilling（2026-08-17）で確定。ADR-0053 §2 を書き直した

## 背景

8 文字の省略形を使わないという規則は SDR-722ce265-2aaf-4a90-915d-32d26b7a38bb が決めた。本 ADR は、その禁止を
どう担保するかだけを決める。担保の方法は、禁止の規則を変えずに単独で覆せる。後から CI の検出を入れるなら、
本 ADR だけを廃止すればよい。そのため規則とは別の ADR にする。

省略形が書かれる場面は、人が手でファイルを作るときと、人が散文に手で書くときの 2 つある。
省略形はフル ID の前方一致なので、`sara check` は散文中の省略形を検出しない。

## 決定

省略形の禁止は CI の確認では担保しない。ファイルの作成は起票ラッパーで機械化し、既存の
item はファイル名と散文の両方をフル ID へ全面移行して、模倣される省略形をリポジトリに残さない。

散文に手で省略形を書かれる残余リスクは受け入れる。

## 根拠

起票が機械化され、リポジトリに省略形の実例が 1 つも無ければ、人が省略形を新たに書くことはほとんど
無い。残るリスクは、CI の確認を維持するコストに見合わない。

## 棄却した代替案

### 散文を走査して省略形を CI で検出する

フル ID を書いた行も先頭 8 文字を含むので、「8 文字の後に UUID の続きが無い」という否定形の判定が
要る。Markdown のリンク・コードブロック・表の折り返しで誤検出が起きる。
