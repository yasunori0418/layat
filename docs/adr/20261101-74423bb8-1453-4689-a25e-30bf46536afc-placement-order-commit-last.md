# ADR-74423bb8-1453-4689-a25e-30bf46536afc: 配置順とコミット最後

- ステータス: 採用
- 日付: 2026-11-01
- 関連: ADR-0044, ADR-0057
- 起点: ADR-0006 §決定（部分失敗 = コミット最後）を書き直した

## 背景

1 回の適用は、複数の FS 操作（新規配置・張替え・stale 除去）と世代のコミットからなり、途中で
失敗しうる。任意のパスへ置く以上、FS 全体を atomic に切り替える手段は無い。操作の順序と、
どこをコミット点にするかを決める必要がある。

## 決定

新規配置と張替えを先に行い、stale 除去を最後に行う。FS への反映が全て成功してから世代を
コミットし、このコミットを唯一のコミット点とする。途中で失敗したら非ゼロで中断してコミットせず、
前の世代を保つ。クラッシュで FS が部分適用のまま残ることは受け入れ、冪等な再実行で収束させる。
エラーを検知したときに FS を適用前の状態へ戻す手順は ADR-0044 が決めている。

配置前の除去や copy の反映を含む実行段の順序は REQ-1be4d678-959c-44d7-a346-44bfd95af56e、
張替えの手順と再実行による収束は REQ-61856da1-8883-401e-ad57-9f326b96d400 に置く。

## 根拠

現状を壊す操作より先に新しい状態をそろえておけば、途中で止まっても旧配置の大部分が残る。
コミットを最後に置くと、積まれる世代は常に完全に適用し終えた状態を指す。クラッシュで残った
部分適用は、同じ manifest を再適用すれば収束するので、一時的なずれは許容できる。

## 棄却した代替案

### 世代を先にコミットしてから FS へ反映する

途中で失敗すると、世代が適用し終えていない状態を指す。次の適用の baseline が実際の FS と食い違う。

### stale 除去を先に行う

途中で失敗すると、旧配置も新配置も無い target が残る。
