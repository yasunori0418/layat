# ADR-8357b519-cb23-4984-ba56-254046779f47: 配置前除去による移行を warning にせず -v のときだけ報告する

- ステータス: 採用
- 日付: 2026-11-03
- 関連: ADR-36bfbfbd-f1dd-4581-a75a-943d80f6ccf5, ADR-3dc21349-5504-48a4-ab88-812b92c3bdf9, ADR-a19bf484-368d-4d01-b539-52de32510fa5, ADR-3b8175b9-5ebf-4123-8855-f698dc843d6b, GitHub Issue #170
- 起点: dotfiles 側での実遭遇（#170）と、次期マイルストーンの grilling セッション（2026-07-11）で設計確定。ADR-0046 §4 を書き直した

## 背景

自分が記録して古くなったものを配置前に除去して移行する（ADR-3b8175b9-5ebf-4123-8855-f698dc843d6b）とき、
除去したことを利用者へどう伝えるかを決める必要があった。layat は成功したときに何も出さず（ADR-36bfbfbd-f1dd-4581-a75a-943d80f6ccf5）、
配置のレポートは `-v` を付けたときだけ出す（ADR-3dc21349-5504-48a4-ab88-812b92c3bdf9）。

## 決定

配置前除去で除去したものは warning にせず、通常の配置レポートと同じく、
`-v` を付けたときだけ報告する。`--dryrun` では、自分が記録して古くなったものの除去を conflict ではない除去として
示し、foreign な祖先は conflict として示す。

報告の規範は REQ-c9ab91c1-f778-4f87-a2ea-c66d6b3c2575 と
REQ-8ef34101-8150-4124-92d5-94fabe6b5d90 に置く。

## 根拠

自分が記録して古くなったものの除去は、意図された安全な操作である。自分で置いたものを自分で消している
だけで、利用者が対処すべきことは無い。成功時の沈黙という出力の規律にそのまま従う。

意図された操作を warning にすると、本当に注意すべき warning（foreign な symlink の上書きなど）が
埋もれる。

## 棄却した代替案

### 移行のたびに warning を出す

利用者に対処の要らない出力が増え、本当に注意すべき warning が埋もれる。
