# DSG-1361df1a-31c4-46ed-a6ce-92938f94ac02: リポジトリを lib / cmd / internal / templates / modules のトップレベル 5 ディレクトリへ分ける

## 設計

`flake.nix` を唯一の entrypoint とし、その下にトップレベル 5 ディレクトリを並置する。

```
<project>/
├── flake.nix              # outputs を定義（packages.layat / lib / templates / modules）
├── flake.lock             # flake 入力のロック
├── lib/                   # 純データ生成（nixpkgs.lib のみ依存）
├── cmd/layat/              # layat CLI のエントリポイント（packages.layat）
├── internal/              # 配置・diff・保守的 stale 除去の純ロジック（Go ライブラリ）
├── templates/             # nix flake init -t 用
└── modules/               # 各モジュールシステムへの統合層
```

各ディレクトリの内訳は個別の design item が持つ（`lib/` は DSG-e4d5db6b-5bac-4fd6-b2fb-ed07bdec30f5、`cmd/layat` と
`internal/` は DSG-7d354fe0-a333-495b-9f4b-14bba316dc47、`modules/` は DSG-aeb5e219-4784-4950-845c-35f9bab9179c）。

この分け方が満たしているのは、REQ-f4d7d4ab-fbdb-48c6-b29f-08dd88e72645 が要求する CLI と engine の 2 層構成、
REQ-d85f0cef-0f1e-4897-a841-41b61a8dae51 が要求する lib の依存制約、REQ-b74a118a-1272-44eb-944c-7725163211c6 が要求する engine の内部層への
封じ込めの 3 つで、それぞれが**別ディレクトリとして物理的に分かれている**ことが
実現手段になる。

- `lib/`（Nix）と `internal/`（Go）が別ツリーなので、REQ-d85f0cef-0f1e-4897-a841-41b61a8dae51 の「lib は配置
  ロジックを持たない」が構造として保たれる。lib から engine を呼ぶ経路がそもそも無い
- `internal/` は Go の言語機能で外部モジュールから import できないため、REQ-b74a118a-1272-44eb-944c-7725163211c6 の
  「engine を内部層に閉じる」がコンパイラに強制される。公開 API 面は `cmd/layat` のみ
- `cmd/layat` と `internal/` を分けることで、REQ-f4d7d4ab-fbdb-48c6-b29f-08dd88e72645 の 2 層境界（`manifest.json`）が
  パッケージ境界と一致する
