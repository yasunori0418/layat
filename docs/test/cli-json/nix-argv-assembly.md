# entrypoint の探索順序と nix へ渡す引数列が形ごとに正しく組み立てられる

## 条件

nix を実際に起動せず、起動する直前の引数列までを確かめる。探索と組み立てを純粋な関数として
切り出し、実 FS 上に空ファイルを置いた fixture に対して評価する。

- **探索順序** — flake の entrypoint を最優先とし、次に legacy の候補を順に見る。この順序が
  ディレクトリを明示したときと、カレントディレクトリから自動で探すときの双方で同一である
- **明示指定のバリエーション** — ファイルを直接指定したときは名前から形（flake か legacy か）が
  決まる。認識できないファイル名・存在しないパス・対象ファイルの無いディレクトリはいずれも
  エラーになり、利用者に知らせずに別の候補へ移らない
- **引数列の 2 形式** — flake 形は entrypoint と attr path を 1 つの installable として組み、
  attr path にシステムの次元を含む。legacy 形はファイル指定と attr path を分けて渡し、
  システムの次元を含まない。この差が attr path の組み立てに閉じており、それ以外の nix 呼び出しの
  組み立てを分岐させない
- **テンプレート展開の引数列** — 既定の参照先と、環境変数で局所の参照先へ差し替えた場合の
  双方で同じ形の引数列になる
