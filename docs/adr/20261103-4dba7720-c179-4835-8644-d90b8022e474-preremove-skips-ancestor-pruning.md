# ADR-4dba7720-c179-4835-8644-d90b8022e474: 配置前除去は空の祖先ディレクトリを剪定しない

- ステータス: stable
- 日付: 2026-11-03
- 関連: ADR-3b8175b9-5ebf-4123-8855-f698dc843d6b, GitHub Issue #175, #172
- 起点: epic #172 の grilling セッション（2026-07-12）で確定。ADR-0047 §5 を書き直した

## 背景

layat は target を除去した後、空になった親ディレクトリを root の手前まで剪定する。配置前除去
（ADR-3b8175b9-5ebf-4123-8855-f698dc843d6b）も target を除去するので、この剪定を呼ぶかを
決める必要があった。

## 決定

配置前除去は、unlink と rmdir のどちらが成功しても空の祖先ディレクトリの剪定を呼ばない。
剪定は最終段の除去（古くなった配置の除去・`reset`）に限る。

剪定の適用範囲は REQ-8409db86-a1ba-4053-86dc-588985cc1ca7 に置く。

## 根拠

配置前除去で消したものは、直後の配置で同じ場所に置き直す。剪定しても、その場で作り直す
だけの無駄な往復になる。

配置前除去の列には、子から親の順に unlink と rmdir が明示して並んでいる。途中で剪定を挟むと、
まだ実行していない後続の rmdir の対象を先に消してしまい、レポートが不正確になる。配置の
target と無関係な外側の祖先まで剪定するおそれもある。配置前除去は、計画どおりに除去する
ことだけを受け持つ。

## 棄却した代替案

### 他の除去の処理と同じく、配置前除去でも剪定する

除去の処理がそろうが、後続の rmdir の対象を先に消してレポートが狂い、直後の配置で作り直す
ディレクトリまで消すことになる。
