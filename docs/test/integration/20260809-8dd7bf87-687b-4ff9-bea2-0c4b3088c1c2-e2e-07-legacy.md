# CASE-8dd7bf87-687b-4ff9-bea2-0c4b3088c1c2: e2e 07-legacy — 非 flake entrypoint から同じ配置と出力契約を通す

## 対象

`tests/e2e/scenarios/07-legacy.sh`

## 検証内容

- 定めた canonical の形（シェル定義の属性として config を公開する形）で複数の config を
  持つ非 flake の入口を作り、名前を指定した適用が配置を行うこと
- 全件指定がこの入口でも複数の config を適用すること
- layat のための属性を足した状態でも素の nix-shell として動き、入室時のフックが配置を起動
  する入口として働くこと（配置物を消してから入室し、再配置されることで確かめる）
- 機械可読出力の形が入口によって変わらないこと（パス列挙の情報が同じ形で得られる）

評価を再現可能にするため、使い捨ての probe で lock が pin する nixpkgs の store パスを求め、
探索パスをそこへ固定してオフラインで評価する。この経路では配置元が store へ入らず作業木の
パスのまま解決されるため、配置物が store の物であることは意図的にアサートしない。
