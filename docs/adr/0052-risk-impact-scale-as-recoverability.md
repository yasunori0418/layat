# ADR-0052: risk の impact スケールを検出後の回復可能性へ純化する — detectability 第 2 軸は採らない

- ステータス: 採用
- 日付: 2026-08-13
- 関連: GitHub Issue #303, #292, PR #299, PR #302
- 改訂対象: なし（ADR を持たない規約の改訂。`docs/agents/sara-graph.md`「How a risk is scored」節の
  `impact` 行定義と、その top-down 注記が対象）
- 起点: Issue #303 の着手前 grilling（2026-08-12）で確定

## 背景

risk の `likelihood` / `impact` / `level` をどう選ぶかの規約は PR #299 で
`docs/agents/sara-graph.md` へ導入された（対応する ADR は無い）。その `impact` の high 行は
「ユーザー環境・実データの破壊」と「沈黙の不整合（silent inconsistency）を残すこと」を並置し、
さらに top-down の読み方として「開発内に留まる脅威でも、黙って通るなら confinement 行ではなく
silent inconsistency 行を採る」と定めていた。

この規約を全 risk へ横断適用した #292（PR #302）の結果、RISK 全 32 件のうち `impact: high` が
29 件（91%）・`level: high` が 24 件（75%）となり、セル分布は
`likelihood: medium` × `impact: high` に 21 件が集中した。`sara report` で risk を並べても
序列がほぼ付かない状態である。

これは個別 item の判定誤りではない。layat の脅威はほぼ全てが「配置結果が黙ってずれる」形を
とる——symlink が消えている・別物に張り替わっている・manifest の意味が食い違う——ため、
silent inconsistency 節の述語がドメインのほぼ全域を覆う。PR #302 の 3 レンズレビューは独立に
同じ診断へ達し、いずれも「high 行の述語の広さによる構造的帰結であって、再採点では解けない」と
結論した。

## 決定

### 1. `impact` を「検出後の回復可能性」の一軸へ純化する

`impact` の行定義から silent inconsistency 節を外し、次の 3 行にする（正本は
`docs/agents/sara-graph.md`）。

| 値 | 何が懸かっているか |
|---|---|
| `high` | ユーザーに届いてその環境・実データを破壊する。または、気づいた後も再実行・再ビルドでは回復できないものを残す |
| `medium` | 出荷物が誤動作する（沈黙かどうかを問わない）が、気づけば再実行・再ビルドで回復する |
| `low` | 開発内に閉じ、出荷物へは届かない |

`medium` 行が「沈黙かどうかを問わない」と明示するのは、旧規約の読み癖——沈黙するなら
`high`——を打ち消すためである。この節を落とすと、改訂前の判定基準が暗黙に生き残る。
`medium` の主語を出荷物に限るのは、行を top-down に読んだときに `low` 行へ到達する経路を
残すため。主語を置かないと「誤動作するが再実行で回復する」が開発内の脅威まで飲み込み、
`low` が選べなくなる（決定 2 の継承則だけがこの分界の例外になる）。

**1 つの risk が複数の失敗方向を持つときは、最も重い方向で行を採る**。平均や最も起こり
やすい方向で採ると、その risk を立てた理由そのものである最悪経路が消える。ある方向を判定から
外してよいのは、**別の risk がその方向を自分の射程として明示している**ことを確かめて名指し
できるときに限る。確かめずに委譲すると、受け取り側の射程が実はその方向に届いておらず、
どちらの item も計上しないまま重い方向が corpus から抜け落ちる。

**沈黙性（気づけるか）は各 risk 本文の散文に残す**。脅威の性質として重要な情報であることは
変わらず、失われるのはスコアの軸としての地位だけである。

### 2. 検証ゲートの形骸化は「継承則」で採点する

検証ゲートが黙って形骸化する risk（テストが緑なのに何も検査していない類）の `impact` は、
**そのゲートが捕まえるはずの regression の impact を継承する**。ゲート自身が開発内で完結する
ことを理由に `low` へ落とさない。

旧規約はこの類型を silent inconsistency 節で `high` へ引き上げていたため、節を外すと軒並み
`low` へ落ちる。それは誤りで、テストの検出力の喪失は「守っていたはずの脅威が無防備になる」
という形でしか現れない。継承則はこの引き上げを、沈黙性ではなく守備対象の重さに紐づけ直す。

継承則は自動的に `medium` を意味しない。パス安全性のように守備対象そのものが実データ破壊で
あれば `high` を継承する。1 つのゲートが複数の regression を守るときは、決定 1 の最重方向則を
継承元にも適用し、最も重い守備対象を継ぐ。

**継承元は item 本文に名指しする**。可能なら regression を記述するのではなく、それを持つ
`risk` の ID を挙げる。継承先の値は継承元の値に従属するので、名指ししておかないと継承元を
再採点したときに追従すべき item を機械的にも人手でも辿れない。

### 3. `likelihood` の行定義と `level` マトリクスは触らない

二軸を同時に改訂すると再採点の差分がレビュー不能になる。`impact` 改訂後もなお解像度が
足りなければ、そのときに別途 `likelihood` を扱う。

## 検討した代替案

### detectability（気づけるか）を第 2 軸として追加する

`impact` から沈黙性を外すかわりに独立した軸として持ち、`level` を三軸から導く案。**採らない**。

理由は、この軸が layat では飽和して序列情報を持たないことである。沈黙性は上述のとおり
ドメインに遍在するため、detectability も `impact` と同じ 29/32 の偏りを再現するだけになる。
その代償として `docs/model.yaml` の schema 変更（フィールド追加）・全 32 件への値の追記・
`level` 導出マトリクスの 9 セル → 27 セルへの拡張が必要になり、得られる序列は現状と変わらない。

この案は「沈黙性は捨てるには惜しい情報だ」という直感から繰り返し浮上しうる。惜しいのは
事実であり、だからこそ散文へ残す（決定 1）。軸として持つことの是非は情報の価値ではなく、
**その軸が corpus を分割できるか**で決まる。layat では分割できない。将来この判断を覆すのが
妥当になるのは、沈黙する脅威と可視な脅威が同程度の数に分かれるほどドメインの性質が変わった
ときである。

### 再採点だけで是正する（規約は据え置く）

規約の high 行の述語が広いことが原因なので、規約を据え置いたまま再採点すれば規約違反の
corpus になる。PR #302 の 3 レンズが独立にこの結論を否定した。

### `level` マトリクスを調整して high の出現を絞る

`impact` の分布が偏ったままマトリクス側で吸収する案。`impact: high` が 91% を占める事実は
変わらないので、`impact` を見る `sara report` の序列は回復しない。原因ではなく症状への対処。

## 影響

- `docs/agents/sara-graph.md`: `impact` の行定義を差し替え、top-down 注記を継承則へ書き換え、
  行の主語による分界・最重方向則（と委譲の条件）・継承元の名指しを明記
- `docs/risks/` 全 32 件: 新スケールでの再採点（`impact` と、マトリクス導出による `level`）と
  本文のスコア根拠の追従。結果は `impact` が high 21 / medium 11 / low 0、`level` が
  high 17 / medium 12 / low 3 で、飽和していた `impact: high` は 91% → 66%、`level: high` は
  75% → 53% へ下がった。`impact: high` が過半に残るのは、layat の脅威の多くが実際に
  「記録に残らない場所へ書く」「記録外の実体を消す」形でユーザーの実データへ届くためで、
  件数を合わせるための引き下げはしていない。`low` が 0 件なのは行が到達不能だからではなく、
  開発内に閉じる risk（評価スイート・層分割の侵食）がいずれも検証ゲートとして継承則に当たり、
  守備対象の重さを継ぐため
- `dev/tests/risk-matrix.sh`（→ Issue #303 PR-1）は `level` の導出関係だけを見るので、
  再採点の前後どちらでも通る。マトリクス自体を変えないため同テストの更新は不要
- Issue #303 は本 ADR を含む PR でクローズ

`justifies` に INF-659b139d-0cf8-4c65-b30d-93c5ee2dfc71 を張るのは、本 ADR が決めたのが risk item の書き方の規約であり、
その規約を載せる `docs/agents/sara-graph.md` と、`level` 導出を機械検証する
`dev/tests/risk-matrix.sh` がいずれも同 item の担う検証基盤の一部だからである
（ADR-0048 / 0049 / 0050 / 0051 と同じ張り先）。ただし同 item の部品表は `risk-matrix.sh` を
まだ挙げていない。この追記は本 ADR を起こした PR の編集境界の外なので、別 issue で回収する
（未起票）。
