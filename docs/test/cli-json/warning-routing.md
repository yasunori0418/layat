# TC-71fdbbfb-cf81-4aba-8254-59d7cb45d5ab: warning が対象の有無で item と subject へ振り分けられ全種別がコードへ写る

## 条件

warning の置き場所が、その warning の指す対象がインベントリに存在するかどうかで決まることを
確かめる。判定軸はインベントリへの帰属だけであり、警告の種別ではない。インベントリに載って
いる対象への警告はその item が持ち、インベントリの外にある対象への警告は subject が持つ。
後者は item が無い以上どの item にも紐づけられないため、警告自体が対象を自己完結して示す
必要がある。

同じ判定軸が実行の種類によって逆の結果になることも確かめる。配置系では、前世代にしか無い
孤児や保守的判断で残した古くなった配置はインベントリの外にあるため subject 側へ載る。撤去系では
インベントリが撤去対象の全数であり保守的に残した対象もそこに含まれるため、同じ種類の警告が
item 側へ載る。種別で置き場所を決める実装になっていないことを、この対比で確かめる。

あわせて、engine 側の警告種別が漏れなく機械可読なコードへ写ることを確かめる。種別ごとの
対応を網羅的に見るのは、種別が増えたときに写像を足し忘れると、その警告だけが未知の種別として
扱われるため。未知の種別が来たときのフォールバックも定める。

warning と error が同じ文書に同居する場合でも、文書が適合を保つことを確かめる。警告があること
と失敗していることは独立であり、警告の存在が失敗の表現を損なってはならない。
