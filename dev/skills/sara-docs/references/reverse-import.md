# 逆算移行（reverse import）— 既存テスト資産から item を起こす

**これは規範外の移行専用手順**。新規の作業は SKILL.md の「forward の張り方」に従う
（REQ/DSG → risk → TC → CASE の順に、親が先に在る状態で起こす）。この手順を使ってよいのは、
**sara 導入前から存在するテスト資産**に item の裏付けを後付けするときだけ。forward で
起こせる場面でこの手順に流れない（「実装が先にあるから」は、その実装がこの導入・移行の
一部であるときのみ理由になる）。

## 順序

forward と逆に、実体に近い側から束ねながら遡る:

1. **棚卸し** — 対象のテスト資産（テストファイル・シナリオ・check）を列挙する。
   CASE を持たせない資産（lint・カバレッジ計測などの品質系）は先に除外し、
   除外理由を記録する（プロジェクトが除外リストの正本を持つならそちらへ）。
2. **CASE を起こす** — 資産 1 つにつき CASE 1 件（1:1）。`resource` に正準表記、本文に
   対象の説明と主な検証内容（テスト関数のテーマ列挙）。テスト関数単位には割らない。
   CASE から主担当の TP へ `follows` を張る。
3. **TC へ束ねる** — 同じ不変条件・観点を検証する CASE 群を検証テーマ単位で束ね、
   TC を起こして CASE から `covers` を張る（対象あたり数件が目安）。
4. **RISK へ束ねる** — TC 群を「このテーマが壊れると何が起きるか」の脅威単位で束ね、
   risk を起こして TC から `mitigates` を張る（対象あたり 2〜5 件が目安）。
5. **threatens を張る** — 各 risk が脅かす REQ / DSG を特定して `threatens` を張る。
   ここで張り先の REQ / DSG が**存在しない**ことが判明したら、それは仕様の欠落。
   REQ / DSG を代作せず、仕様起こしを提案して停止する（forward の原則がここでも効く）。

## 途中状態の扱い

逆算の途中は構造的にギャップが残る。`covers` も `follows` も持たない CASE は strict check の
orphan error になる。`follows` だけを持ち `covers` が無い CASE は orphan error にならず
strict check を通るが、この場合も**束ねる先を起こすまでは commit 単位を跨がない**。
`sara check` green を保てる単位（CASE + TC + risk + threatens を揃えた一塊）で進め、
残りの未着手は `sara-gap` で追跡する。

## 逆算で作った item の品質

逆算でも item の品質基準は forward と同じ:

- risk の likelihood / impact には根拠を書く（「テストがあるから low」ではなく、
  変更頻度・検証ゲートの届き方・回復可能性から見積もる）
- 実在しない脅威を起こさない（到達しない防御分岐を risk に計上しない）
- TC は検証テーマであってテストケースの列挙ではない（粒度は工程スキルの粒度ガードに従う）
