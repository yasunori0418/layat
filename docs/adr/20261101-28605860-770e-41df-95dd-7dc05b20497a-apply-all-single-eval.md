# ADR-28605860-770e-41df-95dd-7dc05b20497a: apply --all は config ごとの情報を 1 回の eval でまとめて取る

- ステータス: 採用
- 日付: 2026-11-01
- 関連: ADR-2f472fc4-23ed-4169-aa49-8bded9e336d9, ADR-955c2601-88fb-4be8-85de-ec7d0a8c727d, ADR-9e328362-2e90-441a-8eca-40081ce71b1b, ADR-feb60906-1517-46b8-8fa5-e007df4d3e11, ADR-f607b605-c69e-4c7e-ac89-75b7bce5bee1, ADR-ad1c2507-1f42-4cd3-ab56-9183892f8988, ADR-777fc3c8-4ca8-49da-aaf3-146b7d991ebe, ADR-b3f3b68e-5096-46d1-bafd-53a9ab4711f4, GitHub Issue #550
- 起点: 実装前残セマンティクス確定の第6巡（2026-06-14）で確定。ADR-0024 §8 を書き直した

## 背景

apply は build の前に eval で rootKind を先に読み、root と profileDir を決める（ADR-02170bb7-d3b6-49ae-8426-de2113951637）。
`apply --all` で config ごとに eval すると、config の数だけ nix の評価プロセスを起動することになる。

## 決定

`apply --all` は、全 config の rootKind などを 1 回の eval でまとめて取り、root モードのフィルタと
profileDir の確定にその結果を使う。build だけは、config ごとの atomic 性を保つために config ごとに
行う。

一括 eval で取る項目と式の形は REQ-535b811d-dfc5-4eac-92db-737e70eb5415 に置く。

## 根拠

eval のプロセス起動は config の数に比例して重くなる。1 回にまとめれば、起動のコストは config の
数に依らず一定になる。build を分けるのは、1 つの config の build 失敗を他の config に波及させない
ためである。

同じ一括 eval で config ごとの target 一覧も取れるので、config 間の target 衝突を適用前に止める
処理（ADR-75df92ae-0694-452b-8fb4-350994e31b25）も、eval の回数を増やさずに行える。

## 棄却した代替案

### config ごとに eval する

実装は単一の apply と同じ処理で済むが、eval の起動コストが config の数だけ掛かる。
