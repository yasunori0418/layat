# ADR-e8bb6153-2528-419e-8be0-c862a3eb4e05: layat.jobs で activation の並列度を指定する

- ステータス: 採用
- 日付: 2026-11-03
- 関連: GitHub Issue #585, `docs/spec.md`
- 起点: ADR-0061 §2 を書き直した

## 背景

activation は `apply --all` を 1 回起動し、build と配置を `--jobs` の並列度で実行する。CLI の既定
（論理 CPU 数）で足りる場面は多いが、switch のときの負荷を抑えたい利用者もいる。起動文字列は
モジュールが組み立てるので、並列度を指定するオプションが無ければ、利用者は並列度を変えられない。

## 決定

共通オプション `layat.jobs :: ints.unsigned`（既定 0）を設け、activation の起動へ `--jobs <n>` として
渡す。0 は論理 CPU 数を表し、`--jobs` の解決規則に従う。

共通オプションの集合は REQ-fc1c7ce6-dc9d-4dd3-98f5-7877d9f99d10、activation での `--jobs` の
渡し方は REQ-c847d1af-a437-46bb-bd64-42083810d034 に置く。

## 根拠

- 並列度を下げたい利用者のためにオプションを設ける。既定の 0 は CLI の既定と同じ意味なので、指定しない
  利用者の挙動は変わらない
- 型を `ints.unsigned` にして、`--jobs` が拒否する負数をモジュールの評価時の型チェックで弾く

## 棄却した代替案

### オプションを持たず CLI の既定に任せる

並列度を下げたい利用者が activation に介入する手段が無くなる。

### 型を `int` にして負数の拒否を CLI に任せる

誤った値が switch の実行時まで見えない。評価時の型チェックで止められる誤りを先送りする。
