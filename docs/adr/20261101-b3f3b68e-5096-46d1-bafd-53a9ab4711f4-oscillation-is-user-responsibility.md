# ADR-b3f3b68e-5096-46d1-bafd-53a9ab4711f4: 配置の振動はユーザー責任とし、文書で注意するに留める

- ステータス: 採用
- 日付: 2026-11-01
- 関連: ADR-0017, ADR-0031, GitHub Issue #550
- 起点: 実装前残セマンティクス確定の第5巡（2026-06-14）で確定。ADR-0023 §5（5b）と ADR-0024 §10 を書き直した

## 背景

別の config A と B が同じ target を狙うと、ドリフト修復（ADR-0017）と cross-config の後勝ちが
組み合わさって、配置が往復し続ける。A が置き、B が foreign として奪い、次の shellHook で A が
取り戻す、という動きである。1 回きりの後勝ちと違い、シェルに入るたびに繰り返す。そのたびに
foreign symlink の warning も出る。

## 決定

この振動は「同じ target を複数の config で狙わない」というユーザーの責任とし、検知して止める
機構も、warning を抑えたりまとめたりする機構も持たない。warning は振動のあいだ出続けてよく、
直し方（config 間の target の重複を解消する）は文書で注意するに留める。

振動を可視化する warning の規範は REQ-fc1118b1-b0e8-4ddf-80f6-c70956651693 に置く。

## 根拠

振動は設定ミスの症状で、warning が出続けることがそのシグナルになる。抑えたりまとめたりすると、
直すべき設定ミスが見えにくくなる。warning は成功時に沈黙する出力規律（ADR-0031）でも常に stderr に
出るので、ユーザーの目に届く。

振動を止めるには、どちらの config が正しいかを engine が判断する必要がある。その判断材料は engine に
無い。

## 棄却した代替案

### 振動を検知して配置を止める

どちらの config を勝たせるかを engine が決められない。検知のために配置の履歴を profile の外に
持つ必要も出る。

### 同じ warning を抑える、またはまとめる

設定ミスのシグナルを弱めるだけで、振動は止まらない。
