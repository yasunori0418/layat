# 用語（`ubiquitous_term`）

* [generation](./20261107-10bcf077-1e99-456b-bb0a-c9b87daf526e-generation.md) - The unit of rollback. The default generation backend, nixprofile, manages it on layat's own Nix profile (the `nix-env --profile <dir>` style). nixprofile commits (`--set`) and switches (`--switch-generation`, which rollback also uses) generations with `nix-env --profile <dir>`, and lists them by scanning the generation links (`profile-<N>-link`) in the profileDir read-only, without `nix-env`; pruning (`--delete-generations`) and store GC (`nix-collect-garbage`) are left to the user's nix commands.
* [subpath](./20261107-12218337-953b-40c8-b9ec-6d8ee8ec0d4e-subpath.md) - The relative path selecting which path inside src to take, for an entry. Works for both files and directories; default `"."`. Omitting `subpath` is the canonical way to select the whole repository (`subpath = "."` is the explicit form).
* [generation backend](./20261107-1660e016-7a0a-4319-9346-466f759fe759-generation-backend.md) - What the engine leaves recording, listing, and switching generations to. Its contract has five operations under `internal/generation`, with paths and integers as the only inputs and outputs: Commit (record a link-farm as a new generation and point the profile at it), List (list the generations, marking the current one), Switch (point the profile at an existing generation), UserBase (the base the user-state profileDirs are keyed under), and SystemBase (the base the system-mode profileDirs are keyed under). The nix implementation (nixprofile, `internal/generation/nixprofile`) is the default and only backend, and the only place that runs `nix-env`; its bases are `<state>/nix/profiles/layat` and `/nix/var/nix/profiles/layat`. The CLI always injects nixprofile, and the engine errors when given no backend. The engine does not care who manages generations; the profileDir layout (`profile` / `profile-<N>-link` / `.pending`) is the fixed part of the contract that the engine reads directly. There is no flag, environment variable, or `layat.toml` key that chooses a backend, and no setting that overrides its bases (→ [ADR-62540f8f-a8ba-4441-97b0-36b50d7862d8](../adr/20261103-62540f8f-a8ba-4441-97b0-36b50d7862d8-generation-backend-contract-paths-and-ints.md), [ADR-9755ba76-4c02-4b4e-a8c0-031a24a3a5b9](../adr/20261103-9755ba76-4c02-4b4e-a8c0-031a24a3a5b9-single-nix-generation-backend.md), [ADR-764ffff1-6b5a-4ed7-89d0-5700eb3ee883](../adr/20261103-764ffff1-6b5a-4ed7-89d0-5700eb3ee883-state-bases-not-configurable.md)).
* [home mode](./20261107-229fb5db-7865-4679-917c-2c067ea571c9-home-mode.md) - The placement mode where root = `$HOME`, selected explicitly with the `homeRoot` marker. Used by both standalone and modules such as home-manager. It commits a generation each time and exposes `--rollback` to the user.
* [out-of-store symlink](./20261107-2340b0fd-6444-4946-94a6-43f874e37615-out-of-store-symlink.md) - A live symlink to a local path, opted into only via an explicit marker. An explicit escape hatch, not a first-class feature. There are two markers. `layat.lib.mkOutOfStoreSymlink "/abs/path"` points to a local absolute path (for live editing of dotfiles under development). For in-repo trees, the root-relative marker `layat.lib.mkRootRelativeSymlink "rel/path"` takes a path relative to the placement root; the engine resolves it against the root at runtime and creates a relative link from the target's parent.
* [layat CLI](./20261107-285b8069-6e9d-4845-a9b5-634e91338bfe-layat-cli.md) - The primary user-facing UX; the `packages.layat` binary on `PATH`. It discovers an entrypoint, obtains a named manifest through a generator (`nix` by default), and has the engine place it. Subcommands include `apply [<name>]`, `apply --all`, `reset`, `rollback`, `list-generations`, `gitignore`, `prune`, and `init`.
* [placement primitive](./20261107-3046d454-1ff1-48e2-9b05-0aad11c52ea6-placement-primitive.md) - The core of layat: a pure function that places a Nix store path at a `root`-relative `target`. It is not hidden behind a module abstraction — users compose it directly.
* [ephemeral placement](./20261107-30bf2772-cc17-483e-9b0c-79bbeab2d0ed-ephemeral-placement.md) - The nature of placements in project mode: regenerated on each clone and never committed to the project, so activation never touches git state.
* [starter](./20261107-3f190b7f-08dc-4b64-ab48-4be319a7d48f-starter.md) - The two templates that `layat init` expands into the CWD: `templates/standalone` and `templates/project`. Each is a minimal scaffold that works right after expansion; the user trims what they do not need and grows it into their own config. layat itself generates no config; the nix `templates` mechanism does the expansion (→ [ADR-d15a216f-b5d6-4df9-9825-b23a341bec1d](../adr/20261101-d15a216f-b5d6-4df9-9825-b23a341bec1d-templates-and-init-fixed-ref.md), [ADR-7b9ecd2c-6b77-43c4-8fb4-3ad034e618e1](../adr/20261103-7b9ecd2c-6b77-43c4-8fb4-3ad034e618e1-templates-minimal-example-with-comments.md)).
* [system mode](./20261107-4cf59313-b234-4534-95c6-d8dd3dbd99a2-system-mode.md) - The placement mode where root = `/`, selected with the `systemRoot` marker. Used for the distro concept (root = `/`).
* [engine](./20261107-4ddb0597-ec0e-47af-8988-6636b2e5aa29-engine.md) - The placement core that owns both placement (native filesystem operations) and stale removal. It takes `manifest.json` as input, invokes only `git` (toplevel) as an external command, and is implemented as a Go library driven by the layat CLI. It leaves recording and switching generations to the generation backend. It does not generate a bash script per config. "Library" here means internal in-binary layering under `internal/`, not a publicly importable, reusable module — the stable surface is the `manifest.json` contract. The engine is stdlib-only.
* [homeRoot](./20261107-55db6ca4-63de-437d-a667-a0e71676e9f1-home-root.md) - The root marker selecting home mode. At runtime it resolves `$HOME` as root. It promotes the previously implicit `$HOME` default into an explicit marker. The applied form `homeRoot { subdir = ".config"; }` keeps root at `$HOME` and places every target under `.config/`.
* [target](./20261107-575f2527-64a9-4f8b-ae68-1131b053cf66-target.md) - The placement destination of an entry, specified as a path relative to root. The `entries` attribute key is the default `target` and is also the entry's identity (the diff key for stale removal, and its uniqueness key).
* [module](./20261107-57c32ea5-8b3d-4b5d-b1f8-daee58ecbe40-module.md) - An integration layer such as standalone, home-manager, the NixOS / nix-darwin modules, or a devShell `shellHook`. It is purely the wiring that kicks the engine; it never places files itself and never translates to `home.file` or `systemd.tmpfiles`.
* [entry / entries](./20261107-5caf1573-b91f-40dd-a414-58b5f49bf0d9-entry.md) - A placement definition. `entries` is an attrset keyed by `target`, where each value is an entry (`{ src; subpath?; target?; method?; }`). The attribute key is the identifier and supplies the default `target`. There is no manual `name` field; key uniqueness is guaranteed natively by Nix attrset keys.
* [src](./20261107-6e764ddd-03ce-4bd1-be53-64d651783241-src.md) - The placement source of an entry (which store path or repository). The default is a store link into the Nix store; out-of-store is opt-in via an explicit marker. It is orthogonal to subpath; do not read `src` as an abbreviation of `source`.
* [last-applied record](./20261107-7e8e239e-e11b-414e-b6e7-295520d6a1a9-last-applied-record.md) - layat's own record of what it last placed under a root — a filesystem fact, not a generation. It lives at `<state>/layat/<key>/last-applied.json`, keyed like the profileDir (`<name>` for home without `--root`, otherwise `<roothash>/<name>` with the backref `.root`). It holds `recordVersion` (2; versions 1 and 2 are both read), `linkFarm`, `appliedAt`, `manifest` (the placed `manifest.json` embedded verbatim), and `origin` (the source of the most recent apply that wrote the record, `{generator, entrypoint, identity}`; `identity` is copied from the manifest when it declares one), so it does not depend on store GC. When the record has an `origin` that differs from the current one (compared by `identity` alone when both carry one), apply warns and continues (→ [ADR-ab47f502-0fc8-4714-9af4-61e0a64732f8](../adr/20261103-ab47f502-0fc8-4714-9af4-61e0a64732f8-origin-mismatch-warns-and-continues.md)). apply (including generation skip) and rollback rewrite it after the filesystem operations succeed and before the generation operation; reset rewrites it after removal and deletes it once every entry is gone. The baseline for stale removal, drift repair, reset's removal set, and rollback's departing generation is taken from the record, else the profile's current generation, else empty; when the record and the profile disagree on `linkFarm`, the record wins with a one-line warning. On the first apply (neither exists) the baseline is empty and a one-line "no last-applied record" warning is printed. A broken record is an error, not treated as absent (→ [ADR-8e253f2e-c255-482a-a0f8-0837e122e80f](../adr/20261103-8e253f2e-c255-482a-a0f8-0837e122e80f-record-read-strictly.md)).
* [store manifest](./20261107-836edea0-547e-4b96-a1b3-783c6ca86bde-store-manifest.md) - The generation-derived record of "what layat placed". Concretely the `manifest.json` (carrying a `schemaVersion`) inside the link-farm derivation, generated by Nix (`lib.mkManifest`) and read by the Go engine — the Nix↔Go contract. It underpins the engine's conservative stale removal (it deletes only layat-managed symlinks that point where the record says, and never touches the user's real files).
* [systemRoot](./20261107-9425b2c7-3f62-4994-9269-cd79dd1261f7-system-root.md) - The root marker selecting system mode (root = `/`). Promotes what was once called a "future absolute-path string seam" into a first-class marker (→ [ADR-400cadd4-0151-470b-92ae-9b11aa8e9bed](../adr/20261101-400cadd4-0151-470b-92ae-9b11aa8e9bed-three-root-markers.md)). Also accepts the applied form `systemRoot { subdir = "..."; }` (see root).
* [generator](./20261107-b3174f13-88f4-4163-8f56-33d41e21cf77-generator.md) - What the layat CLI obtains a manifest from. Its contract has four operations under `internal/generator`: Discover (find the entrypoint), Roots (return the root kind and root without building), Build (place a link-farm that can be committed as a generation — a store path — at the pending path), and DryBuild (return the store path without a gcroot). The nix implementation (nixgen, `internal/generator/nixgen`) is the default. A generator is chosen only explicitly: `--generator`, then `LAYAT_GENERATOR`, then `layat.toml`, then `$XDG_CONFIG_HOME/layat/config.toml`, then the default `nix`. The engine does not care which generator produced the manifest (→ [ADR-bac005fb-fe4d-4a3b-b9e1-517a62fe46c2](../adr/20261103-bac005fb-fe4d-4a3b-b9e1-517a62fe46c2-generator-four-operations.md), [ADR-36cb1e78-90c0-47d2-bbb1-4bfec5db2964](../adr/20261103-36cb1e78-90c0-47d2-bbb1-4bfec5db2964-generator-chosen-explicitly-only.md)).
* [entrypoint](./20261107-ba99246c-fd5b-4469-bb30-afcf33e83699-entrypoint.md) - The Nix config file the layat CLI reads: one of `flake.nix`, `shell.nix`, or `default.nix`. It exposes a named manifest under `layat.<name>`. The config is still written in Nix and evaluated by `nix build`.
* [method](./20261107-bc180161-69ea-4ec6-bae5-9c0e5853a112-method.md) - The entry field that selects the placement kind (renamed from the old `mode`). Renamed to avoid misreading it as a unix file mode.
* [layat](./20261107-c3e66a6c-906d-4083-b7ba-19618539c56c-layat.md) - The name of the tool itself. A compressed coinage of "**lay** \<src\> **at** \<target\>": it places src at target, as the manifest says. It follows the traditional UNIX way of compressing a verb phrase into a command name, as `chroot` (change root) and `getopt` (get options) do. The tool was formerly named nput, whose "n" stood for *nix*; that prefix stopped describing the tool once the engine's only contract became `manifest.json`, regardless of who generates it (→ [ADR-6cd587e8-7aa2-4624-be78-7f6501bf0d6f](../adr/20261103-6cd587e8-7aa2-4624-be78-7f6501bf0d6f-tool-named-layat.md)). Spell it lowercase, including at the start of a sentence.
* [store link](./20261107-d0332595-e976-4942-b218-728e428ecc26-store-link.md) - The core, default placement: a symlink whose destination is a Nix store path. The default path that guarantees reproducibility. "Unification" means making the store the default/core and demoting out-of-store to an explicit exception.
* [projectRoot](./20261107-d0d09a24-f641-447d-b490-d33ca57fe862-project-root.md) - The root marker selecting project mode. At runtime it resolves the git toplevel as root (overridable with `--root`). One of the root markers alongside `homeRoot` / `systemRoot`, following the same "pass a marker to opt into behavior" pattern as `mkOutOfStoreSymlink`. Also accepts the applied form `projectRoot { subdir = "..."; }` (see root).
* [project mode](./20261107-dbbd91ee-1d41-438b-9c6f-6972643741cb-project-mode.md) - The placement mode where root = the project root, selected with the `projectRoot` marker. Its placements are ephemeral placement (not committed); generations and rollback are not exposed to the user. The root resolves to the git toplevel.
* [root](./20261107-e6466d28-6ab6-43be-a370-cca82eb1cfdb-root.md) - The base path for placement. Chosen explicitly via the `root` argument of the public API (there is no implicit default). Its type is a union of `string` (absolute path, fixed at evaluation time) and `marker` (resolved at runtime). The markers are projectRoot, homeRoot, and systemRoot. Each marker also accepts the applied form `homeRoot { subdir = "..."; }`. The applied form does not move root; it is evaluation-time sugar equivalent to prefixing every target with `<subdir>/`.
* [error-wrap convention](./20261107-f5a31977-edde-4c0f-881f-28f709b0ef0b-error-wrap-convention.md) - The convention that an error in the engine is wrapped exactly once, at its origin, with the op and the target path attached, and is not re-wrapped as it propagates.
* [standalone](./20261107-f7799808-267e-40c4-aaa7-d85e568f11c4-standalone.md) - A word with two meanings. First, the CLI on its own (invoking the CLI directly): a launch form, not a placement mode. It is orthogonal to placement mode (home / project / system); the mode is decided by the `root` marker, and the CLI on its own can use both project mode and home mode. Second, home-manager's standalone configuration (using HM without the NixOS module), the sense used by `tests/e2e/scenarios/05-hm` and TP-0734996e-aea9-4229-8075-89a64bdf9f79.
* [prebuilt](./20261107-fbb72ad3-f0d8-4403-8775-705fb0275ade-prebuilt.md) - The generator behind `apply --manifest <link-farm>`: Discover returns the given path, Roots reads that link-farm's `manifest.json`, and Build / DryBuild return the path. It is not one of the `--generator` choices (→ [ADR-1ddf424a-db2c-4bcb-8823-bf7e4326b980](../adr/20261103-1ddf424a-db2c-4bcb-8823-bf7e4326b980-manifest-flag-as-prebuilt-generator.md)).
