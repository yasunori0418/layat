# CASE-233855f7-912c-4477-af32-9a54c82353c3: record_test.go — last-applied 記録の読み書き・baseline の優先順位・各操作での更新

## 対象

`internal/engine/record_test.go`

実 FS（tmpdir）を使い nix は使わない単体・統合テスト。世代バックエンドに `generation.Fake` を
注入し、`OnCommit` / `OnSwitch` で commit とポインタ移動の失敗を作る。記録の書き込み失敗は
`<state>/layat` か記録ディレクトリを書き込み不可にして作る。

## 検証内容

**読み書き**（TC-3c28934c-d098-40a3-b598-1b08117f9cf1）

- 記録が無ければ「記録なし」、書いた記録は読み戻せ、roothash 系列では backref `.root` も置く
- 壊れた JSON・各必須フィールドの欠落や型違い・`recordVersion` ≠ 1 を error にする
- 削除は不在でも error にしない

**baseline の優先順位**

- 記録のみ → 記録、profile のみ → profile、両方無し → 空 + warning、両方一致 → 記録、
  両方食い違い → 記録 + warning
- 壊れた記録は profile があっても error
- 記録が無く profile の manifest が読めなければ、baseline は空で読めなかったことを報告する

**各操作での更新**

- apply 成功後の記録が manifest verbatim・`linkFarm`・`appliedAt` を持つ
- FS 失敗時は記録を書かない。記録の書き込み失敗で apply が失敗し、配置が巻き戻り commit しない
- commit 失敗で記録が profile より先行した後の再 apply は generation skip に入らず、記録を
  baseline に stale 除去と commit を行う。両者が一致した後は skip する
- 記録だけがあり profile が無い（初回 commit の失敗後）ときは skip せず commit をやり直す。
  記録が無く profile が一致すれば skip し、記録を書く
- generation skip 経路でも `appliedAt` が更新される
- 記録の書き込み失敗で generation skip（修復を巻き戻す）・rollback（ポインタを動かさず FS を
  巻き戻す）・reset が失敗する
- rollback はポインタ移動が失敗しても記録が N-1 になっており、成功後も N-1。記録が profile より
  先行していれば、記録にだけある entry を撤去する
- reset は撤去した entry だけを除き（foreign は残す、copy も除く）`linkFarm` を保持し、全撤去で
  記録を削除する。途中失敗（symlink 段・copy 段）でも、FS に残った entry で記録を書き直す。
  記録だけがあり profile 系列が無くても、profileDir と backref を用意して撤去する。記録が無ければ profile の current
  から記録を書く
