# CASE-ff4a842e-dd25-4c75-82ef-185507781d02: paths_test.go — state 基底の解決・roothash の性質・profileDir キーイング・世代リンク名と兄弟パス

## 対象

`internal/paths/paths_test.go`

環境変数（`$XDG_STATE_HOME` / `$HOME`）と入力から profile のパス一式を決める層の
ユニットテスト。

## 検証内容

- **`<state>` の解決** — `$XDG_STATE_HOME` があれば `$HOME` の値によらずそれを使う。
  無ければ `$HOME/.local/state` へ落ちる。`$HOME` も解決できなければエラーにする
- **`<roothash>` の性質** — 同じ絶対 root に対して決定的で、長さが固定
- **キーイングの分岐** — project は `<roothash>`、home（`--root` なし）は `<name>` 直キー、
  home + `--root` 上書きは `<roothash>`、fixed root も `<roothash>`
- **世代リンクの命名** — profile リンクに対する `profile-N-link` の形
- **`.pending` out-link** — profileDir 内の `.pending` として解決される（project ケースで assert）
- **backref `.root`** — roothash 階層（`<name>` dir の親）の `.root` として解決される。
  `<roothash>` キーのモード（project / home + `--root` / fixed）でのみ生じ、home の
  `<name>` 直キーでは空になる
- **backref の読み取り（`ReadBackref`）** — 末尾改行付き（engine が書く形）の絶対パスは
  trim して返る。空・空白のみ・相対パス・`.root` 不在はいずれもエラーになり、root パスを
  返さない
- **roothash 系列の列挙（`ListRootHashSeries`）** — tmpdir に張った基底の直下から、`.root` を
  持つ dir だけを系列として拾い、配下の `<name>` dir を `Names` に載せる。`.root` を持たない
  `<name>` 直キー dir・基底直下のファイル・系列直下のファイルは返らない。`.pending` しか
  持たない `<name>` も世代リンクを持つ `<name>` も同じく `Names` に載る（世代の有無を
  条件にしていないことの担保）。`.root` 単独の系列は `Names` 空で返り、`.root` が読めない
  系列は除外されず `BackrefErr` 付きで返る。`.root` がディレクトリでも `Names` には
  混ざらない（engine が `<name>` と誤認して削除順序規律を壊さないため）
- **基底が「無い」と「読めない」の区別** — 基底が存在しないときは `fs.ErrNotExist` に一致する
  エラー、存在するが列挙できないとき（通常ファイル = ENOTDIR）は `fs.ErrNotExist` に一致しない
  エラーで返る。呼び出し側（engine）がこの区別で「黙って続ける」と「warning を出す」を
  分けられることの担保（→ REQ-c44433a1-7ee7-459a-9aae-7cc42166876f）
- **系列単位の失敗は基底全体を落とさない** — backref を stat できない系列・配下を列挙できない
  系列は、それぞれ `BackrefErr` / `NamesErr` を載せて返り、同じ基底の健全な系列は変わらず
  列挙される。エラーで打ち切るのは基底そのものが読めないときだけ（系列を残して warning を
  出す REQ-c44433a1-7ee7-459a-9aae-7cc42166876f の粒度に揃える）。この 2 経路は権限を落として
  誘発するため root 実行では skip する（→ TP-deb05610-44bc-4962-8939-952392e5fbd0 の横断規約）

  この 2 関数は同層の純関数と違って FS を読むため、table ではなく tmpdir を張って駆動する
  （→ DSG-096dc893-21f4-45e3-9347-986e9275b4d1）。TC-bc653f83-70ce-4920-b7cd-9b70a4cd2cae は
  この 2 関数を名指しで引き受けており、`Prune` 経由の結合は engine 側の CASE が覆う
