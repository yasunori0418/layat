# ADR-fc28d09c-9d52-4539-8838-e9ae5a414594: method の symlink から copy への変更を自動で移行する

- ステータス: stable
- 日付: 2026-11-03
- 関連: ADR-3b8175b9-5ebf-4123-8855-f698dc843d6b, GitHub Issue #175, #172
- 起点: epic #172 の grilling セッション（2026-07-12）で確定。ADR-0047 §2 の symlink から copy への変更を書き直した

## 背景

同じ target で `method` を `symlink` から `copy` へ変えると、前世代が置いた symlink が target を
占めている。copy 側の分類では構造の不一致か foreign になり、conflict か skip になる。移行には
手で `rm` する必要があった。

## 決定

同じ target で method が symlink から copy に変わり、on-disk の symlink が前世代の記録どおり
なら、配置の前に除去（ADR-3b8175b9-5ebf-4123-8855-f698dc843d6b）して copy を新しく置く。
readlink が記録と食い違うときは移行せず、通常の foreign の判定に戻す。

判定の規範は REQ-2b48620a-abaa-43df-a106-954bbba3de56 に置く。

## 根拠

symlink は利用者のデータを持たない。記録どおりの symlink なら自分で置いたもので、消しても
失うものが無い。自分で置いて自分で消すという、自動で移行してよい範囲に収まる。

記録と食い違う symlink は、自分の置いたものだと確かめられない。foreign として扱い、安全側に
倒す。

## 棄却した代替案

### method の変更でも、これまでどおり手で `rm` させる

失うものが無い移行にも手作業が要り、宣言的に管理するという layat の考え方に合わない。
