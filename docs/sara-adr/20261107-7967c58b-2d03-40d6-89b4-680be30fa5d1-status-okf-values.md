# SDR-7967c58b-2d03-40d6-89b4-680be30fa5d1: status を OKF の 3 値にし全ての型に持たせる

- ステータス: stable
- 日付: 2026-11-07
- 関連: GitHub Issue #662, `docs/agents/adr-rules.md`, `dev/tests/adr-supersede.sh`
- 起点: epic #662 の grilling（2026-11-07）で確定。SDR-d5304533-00ae-423b-a459-7c67c1cf093c を書き直した

## 背景

`status` は ADR / SDR だけが持つフィールドで、日本語の 4 値（`提案` / `採用` / `不採用` / `廃止`）を
取ってきた（SDR-d5304533-00ae-423b-a459-7c67c1cf093c）。他の型には `status` が無く、item が
いまも有効かを frontmatter から読めない。

OKF の `status` は `draft` / `stable` / `deprecated` の 3 値である。SDR-bab72f31-7cb1-47a3-bb2d-7876757d86fb で
OKF と互換のキーを足すと決めたので、`status` の値もこれに合わせる必要がある。

## 決定

`status` は全ての型で必須とし、値は OKF の `draft` / `stable` / `deprecated` の 3 つにする。

- `draft` は検討中でまだ有効でない item、`stable` は有効な item、`deprecated` はもう有効でない item
  を表す
- ADR / SDR の 4 値は次のように写す。`提案` → `draft`、`採用` → `stable`、`不採用` → `deprecated`、
  `廃止` → `deprecated`
- 提案を棄却した決定の記録も `deprecated` にする。棄却したことは本文の決定節に書く
- ADR / SDR 以外の既存の item は `stable` にする
- `dev/tests/adr-supersede.sh` は「`supersedes` が指す ADR は `deprecated`」の一方向だけを確かめる。
  「`deprecated` の ADR は `supersedes` から指される」は確かめない

## 根拠

全ての型が同じ 3 値を持てば、型を問わず「いま有効か」を同じキーで絞り込める。OKF の読み手も、
値の意味を OKF の定義で解釈できる。

`不採用` と `廃止` を同じ値にすると、ステータスだけでは両者を区別できなくなる。ただし区別が要るのは
ADR を読む人で、その人は本文の決定節を読む。棄却の記録は「採らない」という決定がいまも有効だという
点で `stable` にも近いが、`stable` にすると「何かを採用した記録」と読まれる。ステータスで区別したい
のは「採用した決定がいまも有効か」で、棄却の記録はその外にあるので `deprecated` に寄せる。

`adr-supersede.sh` の逆向きの確認は、`deprecated` の ADR は必ず後継を持つという前提に立っていた。
棄却の記録が `deprecated` に入ると後継を持たない `deprecated` ができるので、逆向きの確認はやめる。
`supersedes` で指した ADR を廃止にし忘れたときは、一方向の確認で引き続き見つけられる。

## 棄却した代替案

### 4 値を残し、OKF の値は index.md の生成時に写す

item を読む OKF の読み手には日本語の値が見える。値の対応表が生成器の中に隠れ、frontmatter と
index.md で同じ item のステータスが違って見える。

### 棄却の記録を `stable` にする

ステータスだけを見た読者が、何かを採用した記録だと受け取る。これを避けるために `不採用` を設けた
経緯があり、`stable` に寄せると同じ問題が戻る。
