# RISK-3e8dd093-f21f-49c6-8d8c-7d62a6fad1e5: レイアウト移行が部分適用で止まり、再実行しても収束しない

per-file 配置と dir symlink 配置の行き来、および symlink → copy の method 変更は、既存の
配置物を配置前に除去してから新しい形を作る。この配置前除去は「除去してよいか」の判定と
「途中で止まったらどうなるか」の 2 面で脅威を持つ。

判定を誤れば、ユーザーの実体を移行の名目で消す。逆に移行できるはずのケースを conflict にすれば、
設定を変えたユーザーが手作業での撤去を強いられる。そして移行の途中で conflict が見つかったとき、
既に除去した分をそのまま残せば「元の配置でも新しい配置でもない」中間状態が残る。この状態から
再実行しても収束しなければ、ユーザーは手で直すしかなくなる。

method 変更の非対称性（symlink → copy は自動移行し、copy → symlink は conflict に留める）も
この脅威の一部である。copy はユーザー編集を含みうるため自動除去してはならず、対称に扱えば
データを失う。

## 想定する失敗

- 移行判定を誤り、記録に無い実体を配置前除去で消す
- 移行可能なケースを conflict にし、正常な設定変更が進まなくなる
- 除去途中の conflict で部分除去が残り、中間状態から復帰できない
- copy → symlink を自動移行し、ユーザー編集を含む copy を消す
- 中断後の再実行が収束せず、同じ conflict を繰り返す

## 張り先の判断

3 本とも `requirement` へ張る。何を移行し何で停止するかはユーザーが観測する振る舞いであり、
配置前除去という実装手段を別の移行方式へ差し替えても「部分適用で詰む」懸念は残る。
