# ADR-8517e311-c461-41aa-80ac-48760a7762b2: prune はロックを取れない系列を待たずに飛ばす

- ステータス: stable
- 日付: 2026-11-03
- 関連: ADR-ad1c2507-1f42-4cd3-ab56-9183892f8988, GitHub Issue #580
- 起点: 次期マイルストーン計画の grilling（2026-07-04）。公開後の実運用で孤児系列が溜まり始めたことを消費側の要求と判断した。ADR-0034 §2b を書き直した

## 背景

prune が系列を削除している最中に、同じ profileDir で engine が動いていると、apply
が作りかけの世代や記録を消してしまう。apply と reset は profileDir の flock で互いを排他している。

## 決定

prune は各系列を削除する前に、その profileDir の flock を try-lock で取る。取れなかった系列は
warning を出して飛ばし、lock の解放は待たない。

## 根拠

lock を取れないのは、その系列で engine が動いているということだ。root
が実在して使われている強い兆候になる。削除の対象である見込みは極めて低い。

解放を待つと、使用中の系列を消すために待つという倒錯した挙動になる。飛ばした系列は、engine
が終わった後に prune をもう一度実行すれば判定し直せる。

## 棄却した代替案

### lock の解放を待ってから削除する

使用中の系列は削除の対象にならないので、待つ理由が無い。

### lock を取らずに削除する

同時に動く apply と競合し、作りかけの世代や記録を壊す。
