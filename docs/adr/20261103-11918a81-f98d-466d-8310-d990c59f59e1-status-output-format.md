# ADR-11918a81-f98d-466d-8310-d990c59f59e1: status は entry ごとに配置先を出力する

- ステータス: 採用
- 日付: 2026-11-03
- 関連: ADR-c6bc7060-7af4-4889-9ce6-5800601c9dcc, GitHub Issue #580, #198
- 起点: Issue #198（`layat status [name]`）の実装前に、2026-07-19 の grilling 以後の実装の変化を差分 grilling で反映した（2026-10-23）。ADR-0065 §3 を書き直した

## 背景

status の出力には、人が読むテキストとスクリプトが読む `--json` の 2 つがある。
どちらでも「どこに何が置かれているか」を示したい。読み取り系のコマンドは、列挙を `--json`
のエンベロープの info に載せている。

## 決定

テキストは config ごとに apply した時刻を見出しに置き、entry ごとに target・method・配置先（symlink
が指す先）を 1 行で出す。`--json` は `list-generations` と同じく読み取り系の列挙として、
記録の内容を config ごとの info に載せる（ADR-c6bc7060-7af4-4889-9ce6-5800601c9dcc）。行の書式と
info の形は REQ-fa181aa6-29a2-48c3-ae07-cc1b9a3b0303 に置く。

## 根拠

利用者が確かめたいのは、target がどこを指しているかである。配置先は manifest には無く planner
が計算するので、status が計算して出す。1 行に 1 entry を出せば、シェルのコマンドでそのまま扱える。

`--json` を `list-generations` と同じ形に揃えれば、読み取り系のコマンドの JSON を同じ方法で読める。

## 棄却した代替案

### 記録の manifest をそのまま出力する

配置先が含まれず、利用者が確かめたい情報にならない。

### status 専用の JSON の形を作る

読み取り系のコマンドの間で、JSON の読み方が分かれる。
