# ADR-af37a636-a798-4c03-8fa4-e73ed6375a92: apply --all の集約は config 名の辞書順に並べる

- ステータス: 採用
- 日付: 2026-11-01
- 関連: ADR-0038, ADR-0039, GitHub Issue #550
- 起点: ドキュメント計画段階のレビュー（2026-06-13）で確定。ADR-0013 §3 と ADR-0016 §2 を書き直した

## 背景

`apply --all` の結果の表示と、失敗の集約には、決まった並び順が要る。当初は entrypoint の
`layat.*` の定義順にするつもりだったが、`layat.*` は attrset で、Nix の attrset は定義順を
保持しない。

## 決定

`apply --all` の集約表示と結果の並びは、config 名の辞書順（キーのソート順）にする。適用そのものの
順序は結果に影響しないので、規範としては決めない。

並び順の規範は REQ-4cbd9a0d-9f94-4747-8881-56020dc6d5af に置く。

## 根拠

`builtins.attrNames` は辞書順を返すので、辞書順なら Nix 側でも Go 側でも追加の情報なしに決定的な
順序が得られる。各 config は独立した profile で atomic なので、どの順で適用しても最終状態は
変わらない。並びが要るのは、表示と失敗の集約を毎回同じ形にするためだけである。

config を並列に適用する現行の実装（ADR-0039）では、完了の順序が非決定になる。それでも集約を
辞書順に並べ直せば、出力は決定的なまま保てる。同じ entrypoint の config どうしの target 衝突は
適用前に止まる（ADR-0038）ので、適用順で勝敗が変わる場面も残らない。

## 棄却した代替案

### entrypoint の定義順に並べる

Nix の attrset が定義順を保持しないので実現できない。

### 完了した順に並べる

並列に適用すると実行のたびに順序が変わり、出力を比べたりテストで固定したりできなくなる。
