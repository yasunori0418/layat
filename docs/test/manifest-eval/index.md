# manifest-eval

## テスト条件（`test_condition`）

* [アグリゲータの名前衝突の確認が衝突を落とし、衝突元を全件示す](./aggregator-collision-detection.md) - nix-unit のスイートを組み立てるマージ（`tests/nix-unit-lib.nix` の `mergeTests`）が、[評価テストは nix-unit で不変条件を、namaka で manifest 全体のスナップショットを見る](../../test-plan/nix-unit-namaka-split.md) の定めるテスト名の一意性を機械的に強制していることをアサートする。合成した`{ file, tests }` のリストを渡し、readDir が返す実ファイル構成に依存せず throw 側の処理を実行する。
* [GC アンカー名の形式・決定性・特殊文字耐性をアサートする](./anchor-name-determinism.md) - アンカー名（target の sha256 先頭 32 hex）そのものの性質を、farm の組み立てから切り離してアサートする。抽出条件と組み立て結果は [GC アンカー対象の抽出条件と farm の組み立て結果をアサートする](farm-anchor-derivation.md) の担当。
* [省略時の既定適用・明示上書き・target 辞書順での決定的配列化をアサートする](./entry-normalization-defaults.md) - attrset で宣言された entries が配列へ正規化される過程を、3 つの観点でアサートする。
* [GC アンカー対象の抽出条件と farm の組み立て結果をアサートする](./farm-anchor-derivation.md) - symlink farm が GC アンカー専用であることを、対象の抽出と組み立て結果で見る。アンカー名そのものの形式・決定性は [GC アンカー名の形式・決定性・特殊文字耐性をアサートする](anchor-name-determinism.md) の担当で、ここでは扱わない。
* [fixed root で rootKind が fixed になり絶対パスを併記する（home marker が倒れないことを含む）](./fixed-root-absolute-path.md) - `normalizeManifest` の `root` に marker でない絶対パス文字列を渡したとき、出力の `root`オブジェクトが [manifest.json の root は rootKind を持ち fixed のときだけ絶対パスを併記する](../../requirements/manifest-root-object.md) の fixed 側の規定どおりになることをアサートする。
* [manifest 文書全体をスナップショットに固定し、どの不変条件も名指ししない変更を差分として出す](./manifest-document-regression.md) - `normalizeManifest` の出力全体をスナップショットとして保存し、以後の変更が差分として現れるようにする。個別アサートは名指しした性質しか守らないため、フィールドの追加・削除・改名のように「アサートを書き忘れた箇所」の変化はここでしか捕まらない。
* [manifest 文書の形（schemaVersion / root / entry 5 フィールド）を不変条件としてアサートする](./manifest-shape-invariants.md) - `normalizeManifest` が返す文書のトップレベルと entry の形を、値ごとに名前の付いた不変条件としてアサートする。
* [marker の判別と src 種別への変換を単一 entry の境界でアサートする](./marker-resolution.md) - manifest 全体を組み立てずに、単一 entry の解決（`resolveEntry`）と型側の marker 判別述語を直接突いてアサートする。文書の形（[manifest 文書の形（schemaVersion / root / entry 5 フィールド）を不変条件としてアサートする](manifest-shape-invariants.md)）とは別の境界で、変換ロジックそのものを見る。
* [パス脱出判定の深さ境界を private helper 越しに内側・外側の対でアサートする](./path-escape-boundary.md) - `escapesBase` / `isUnsafe` をテスト seam 越しに直接叩き、深さ 0 の境界を内側と外側の対でアサートする。エラーの到達性は [拒否すべき入力が評価時に throw することをアサートする](rejection-gates.md) の担当。
* [拒否すべき入力が評価時に throw することをアサートする](./rejection-gates.md) - 「この入力は評価が失敗する」を、エラー種別と拒否されたフィールドの名指しで直接アサートする。正常系のアサートでは、拒否条件が外れたことを検出できないため。判定ロジックそのものを private helper 越しに単体で見るのは [パス脱出判定の深さ境界を private helper 越しに内側・外側の対でアサートする](path-escape-boundary.md) の担当で、検証境界が異なる。
* [subdir 適用形が全 target に正規化済みの前置を施し、root と単体 marker を変えず、不正な subdir を評価時に拒否する](./root-subdir-sugar.md) - root マーカーの subdir 適用形（[root マーカーの subdir 適用形は全 target への前置と等価な評価時の糖衣で、root を動かさない](../../requirements/root-marker-subdir-sugar.md)）が、全 target への前置と等価な糖衣として振る舞うことを確かめる。
