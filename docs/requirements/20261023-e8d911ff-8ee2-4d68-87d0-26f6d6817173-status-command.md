specification: |
  `layat status [name]` SHALL show what is currently applied by reading the last-applied
  records, without discovering an entrypoint, invoking a generator or running nix eval /
  build, and without reading the profile bases. It SHALL scan the user record base
  `<state>/layat` and then the system record base `/var/lib/layat`, and SHALL list every
  config that has a record in them: the `<name>`-keyed records directly under a base and
  the records of the `<roothash>/<name>` series. Within a base the `<name>`-keyed records
  SHALL come first, in ascending order of `<name>`, and the `<roothash>` series after
  them, in ascending order of `<roothash>` and then of `<name>`, so that the order is the
  same on every run. A `<name>` without a record SHALL NOT be listed. A base that does not exist SHALL be
  treated as empty. A system record base that exists but cannot be read SHALL be skipped
  with one warning line, and a user record base that exists but cannot be read SHALL fail
  the command.

  Each listed config SHALL be named `<mode>:<name>` when it is `<name>`-keyed, the mode
  being `home` for the user base and `system` for the system base, and
  `<mode>:<name>@<root>` when it belongs to a `<roothash>` series, the mode being the
  `rootKind` of the manifest embedded in the record and the root being the value of the
  backref `.root`. When the backref of a series cannot be read, its configs SHALL be named
  `<mode>:<name>@<roothash>`, the series directory name `<roothash>` standing in for the
  root. When the `<name>` entries of a series cannot be listed, or when the backref cannot
  be read and no `<name>` with a record is found under it, the whole series SHALL be
  reported as one error subject named `<mode>:@<roothash>`. For these series, and for a
  config of a `<roothash>` series whose record cannot be read or is invalid, the mode
  SHALL be `home` for the user base and `system` for the system base. When
  `[name]` is given, the listing SHALL be filtered to the configs whose `<name>` part
  equals it exactly, across every base, mode and root, and the error subjects of the
  series reported as a whole (`<mode>:@<roothash>`) SHALL be included as well. When nothing is
  listed, not even such an error subject, the command SHALL write no listing line to
  stdout (under `--json` the envelope carries an empty `results`), SHALL write one
  notice line to stderr and SHALL exit 0.

  A record that cannot be read or is invalid (not valid JSON, a missing or mistyped field,
  an unknown field, or a `recordVersion` other than 1), and a backref that cannot be read,
  SHALL make that config an error and SHALL NOT be treated as the absence of a record; the
  command SHALL continue listing the other configs and SHALL exit 1.

  Without `--json` the command SHALL write, for each config, one heading line
  `# <subject> (applied <appliedAt>)` followed by one line `<target>\t<method>\t<dest>`
  per entry of the recorded manifest, `<dest>` being the destination the entry's symlink
  points to as the planner computes it, and SHALL separate configs by one empty line. The
  command SHALL be read-only: it SHALL NOT take the flock, SHALL NOT create any directory
  or file, SHALL NOT write, rewrite or delete a record, and SHALL NOT check the effective
  user ID.

# REQ-e8d911ff-8ee2-4d68-87d0-26f6d6817173: status は記録基底を走査して last-applied 記録を読み取り専用で表示する

## 仕様

```
layat status            # 記録を持つ全 config を列挙する
layat status <name>     # <name> 部分が完全一致する config に絞る
layat status --json     # outturn エンベロープで出す
```

| 走査順 | 基底 | 基底内の並び | subject 名 |
|---|---|---|---|
| 1 | `<state>/layat` | `<name>` 直キー（`<name>` の昇順）→ `<roothash>` 系列（`<roothash>`、`<name>` の昇順）| `home:<name>` / `<rootKind>:<name>@<root>` |
| 2 | `/var/lib/layat` | 同上 | `system:<name>` / `<rootKind>:<name>@<root>` |

- **データ源**: last-applied 記録（manifest を埋め込み、`appliedAt` と `linkFarm` を持つ）。
  profile 基底は読まない（世代番号は `list-generations` の担当）。nix eval / build なしで
  「今なにが apply されているか」を確かめられる。
- **基底の扱い**: 無い基底は空。system 基底が読めなければ warning を出して飛ばす
  （`list-generations --all` と同じ規則）。user 基底が存在するのに読めなければ失敗する。
- **読めない系列の subject 名**: backref が読めない系列は `<mode>:<name>@<roothash>`、`<name>`
  を列挙できない系列と、backref が読めず記録を持つ `<name>` も見つからない系列は系列全体を
  1 件の `<mode>:@<roothash>` とし、どれも error にする。mode は、記録が読めない config も
  含めて基底に応じた `home` / `system`。
- **`[name]`**: `<name>` 部分の完全一致。mode / root を問わない。系列全体で 1 件として返す系列の
  error subject（`<mode>:@<roothash>`）は、求めた名前が入っている可能性があるので絞り込みでも落とさない。一致 0 件は stdout に一覧の
  行を出さず（`--json` では `results: []`）、stderr に 1 行通知して exit 0。
- **不正な記録**: その config だけを error にして列挙を続け、exit 1。記録の検査は apply が
  baseline を読むときと同じ厳格さで、「記録なし」へ倒さない。
- **テキスト出力**: 見出し行 `# <subject> (applied <appliedAt>)` と entry 行
  `<target>\t<method>\t<dest>`。config の間は空行。
- **読み取り専用**: flock を取らず、ディレクトリ・`.pending`・`.root`・記録を作らない。記録は
  mode 0644 で書かれるので、system 基底も euid の検査なしに非 root で読める。

`--json` の形は REQ-fa181aa6-29a2-48c3-ae07-cc1b9a3b0303、`--json` 時の stdout 専有は
REQ-2353259f-5878-452a-8e11-3445de69abc2、記録の置き場と内容は
REQ-9d622539-a1e5-4719-af51-e0cd85b66f35 と REQ-0d1f557b-7ae7-41ea-b17b-cdb5c80935d4 の担当。
