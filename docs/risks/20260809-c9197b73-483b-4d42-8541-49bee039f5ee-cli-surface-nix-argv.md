# RISK-c9197b73-483b-4d42-8541-49bee039f5ee: フラグ解釈と nix 呼び出しの引数組み立てが仕様とずれ意図しない対象へ作用する

## リスク

CLI の表層は「どの対象に」「どの修飾で」作用するかを決める層であり、ここがずれると、正しい
ロジックが誤った対象に対して正しく動く。engine より下は無傷なので、テストが下層に偏っていると
見逃される。

ずれ方は 3 系統ある。

- **フラグの解釈** — 値を省略できるフラグが直後の位置引数を値として飲み込み、対象の名前が
  消える。あるいは省略時の既定値が配線されず、フラグを付けた意味が失われる。root の種別を
  絞るフラグどうしの排他が効かず、複数指定が黙って片方だけ採用される
- **対象の選択** — 名前省略・明示・全件の 3 経路の区別が崩れる。全件と修飾フラグの合成が
  効かない
- **nix 呼び出しの引数組み立て** — entrypoint の探索順序（flake → legacy）がずれる、あるいは
  flake 形と legacy 形で attr path の組み立てが食い違い、存在しない attribute を参照する。
  テンプレート名の受理集合が緩むと、意図しない参照先を `nix flake init` へ渡す

サブコマンドの登録漏れも同じ層にある。コマンドを足したときに機械可読出力の開始・公開へ
配線し忘れると、そのコマンドだけ契約から外れる。

attr path の解決も同じ層にある。名前を省いたときに `default` 以外へ解決する、manifest を
`layat` 名前空間ではなく `packages` に探す（→ REQ-205d744d-5a53-4511-bc09-892ba01d4e6f）、flake の
`layat.<system>.<name>` と legacy の `-f` 経路で attr path を取り違える
（→ REQ-496b1a07-5b74-416b-9e5f-3952b4c03737）、`apply --all` の rootKind を一括 eval で取らずフィルタの
振り分けを誤る（→ REQ-535b811d-dfc5-4eac-92db-737e70eb5415）と、意図しない config を build する。
entrypoint や `layat.<name>` が見つからないときに別の config を推測するか空の manifest で続ける
（→ REQ-774cef80-2872-4ea1-937b-a0fbabc305a9）、`rollback` が `--all` を受け付ける
（→ REQ-89c7baf9-9be0-417b-bd2d-b2e4edabe796）のも、利用者が求めていない対象へ作用する形である。
attr path と nix へ渡す引数列は TC-69537269-32d7-4e04-8722-806b58e7db7a が、対象の選択は
TC-0c7281f8-cffc-4a53-8fe0-f52d9ea6bd12 が見る。

> **RISK-e916f742-59a3-4202-a316-603a908fd0db との境界**。本 item が扱うのは CLI 表層で引数列を組み立てる過程そのもので、
> どの入口を選んでも同じ配置の意味論が成り立つかは RISK-e916f742-59a3-4202-a316-603a908fd0db の担当。分岐を attr path の
> 組み立て 1 箇所へ閉じ込めるという設計選択そのものへの懸念は、設計を入れ替えれば消える性質の
> ため RISK-e916f742-59a3-4202-a316-603a908fd0db が DSG-92f54490-872a-42ac-bbd7-d06e9ee381c6 へ張って表す。ただしその閉じ込めが実際に成立している
> ことの検証は、引数列を組み立てる層の話なので本 item 側の TC-69537269-32d7-4e04-8722-806b58e7db7a が持つ。

## 影響

意図しない config が適用される、あるいはコマンドが実行できない。impact を medium とするのは、
誤った対象へ作用しても、そこで行われるのは layat の通常の配置——記録外の実体は conflict で
停止し、置かれるのは layat 管理下の配置物——であり、引数の組み立てを直したうえでの `reset` と
再 apply が意図した状態へ収束させるため。フラグが位置引数を飲み込む種類の誤りでは対象の名前が
消えたことが可視の失敗として現れず、別の config へ作用したことに気づく契機が無い。この無音性は
本 risk の中心だが、気づいた後の回復可能性は下げない。

likelihood を medium とするのは、フラグの解釈・対象の選択・nix 引数の組み立てという 3 系統が
コマンドを足すたびに増え、機械可読出力への配線を含めて登録漏れが入りうるため。
