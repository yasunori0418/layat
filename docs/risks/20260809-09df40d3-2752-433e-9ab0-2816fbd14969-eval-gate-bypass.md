# RISK-09df40d3-2752-433e-9ab0-2816fbd14969: 評価時に止めるべき入力が素通りして engine 実行時まで到達する

## リスク

`mkManifest` は `evalModules` による入力検査の単一ゲート（REQ-d1b5b3f5-10a0-400d-9f03-ba00c63d1c34）で、パス安全性
（REQ-6911eab6-12b4-457c-9db4-d7430a9e9b3f）・未知キーと旧名の拒否（REQ-3e446ad9-a6f4-4229-b5c5-184754b0ef51）・entry のフィールドを 4 つに限ること
（REQ-a33a11e3-830d-4142-88ed-4c1fc35e7f74）・意図が矛盾する組み合わせ（REQ-16faf428-77f3-492f-b858-222c5274cbf7）・同一 manifest 内の target 衝突
（REQ-5c6b07da-3d06-414d-8770-4f438234b322）・素の文字列 src の拒否（REQ-99ca5381-6c53-426c-b145-7b4297c53868）を全てここで止める。この検査は
`modules/common.nix` が共有する entriesType にも効く（REQ-fc1c7ce6-dc9d-4dd3-98f5-7877d9f99d10）。

**`systemRoot` の未実装拒否はここに含めない**。この決定（ADR-0013 §5）は ADR-0036 が撤回済み
で、現行の規範は `rootKind = "system"` を正規の値とする（REQ-37b56673-6e40-4a1b-a2a7-5d3c084e3e66）。既存 REQ-16faf428-77f3-492f-b858-222c5274cbf7 /
REQ-c5dfcae6-6094-4850-99e5-bf14530bc60a も同じ理由でこの拒否を規範から外している。実装（`lib/manifest.nix` の throwIf と
`gates.nix` の拒否テスト）に残っているのは ADR-0036 が指示した更新の未了であり、逆算元とすべき
規範ではない。同様に、root 省略時のエラー（REQ-4ec3accc-8bb6-461f-9024-dcf0027849e4 の明示必須）を見るアサートは評価
テストに存在しないため、本 risk は REQ-4ec3accc-8bb6-461f-9024-dcf0027849e4 へ `threatens` を張らない。

**顕在化したときに起きること**: ゲートが緩むと、`..` や絶対パスで root の外を指す target が
engine まで届き、意図しない場所を書き換える。タイポした旧名は黙って無視され、ユーザーは
宣言したはずの entry が配置されない理由を追えない。target 衝突は最後に評価された側が勝ち、
どちらが配置されたか宣言からは読み取れない。いずれも「評価時に止まる」ことが安全の前提に
なっており、実行時まで到達した時点で被害は FS に出る。

## 評価

- likelihood: low — ゲートは型定義とクロスフィールド検査の 1 箇所に集約されており、
  境界条件（`..` の深さ・0 ちょうど）まで含めて nix-unit が対で覆っている。本 risk が
  扱う「止めるべき入力が素通りする」方向、すなわち throw しなくなる退行はこの検査が
  確実に捕まえる（どのゲートが throw したかの取り違えは CASE-879a93da-d22f-4397-84da-3544f8249af1 の部分一致では
  区別できないが、それは素通りとは別の失敗モードで RISK-3de9753f-3fd3-4364-b1ab-64c68c15ec77 の担当）
- impact: high — パス安全性の破れ、すなわち `..` や絶対パスが root の外を指したまま engine へ
  届く経路では、書き込み先が layat の記録に残らず原状回復の対象にすらならない。ここで継承則を
  援用する必要は無い。本 item のゲートは `lib/manifest.nix` の `mkManifest`——`lib` として公開
  される出荷物そのもの——であって、テストスイートのように開発内へ閉じないため、high 行が直接
  当たる（継承則は開発内に閉じるゲートが low 行に取られるのを防ぐための例外で、本 item は
  その例外を必要としない）

## 対処

TC-e7ff0e6d-32d7-4ed6-8c2f-449dba34b2f6（各ゲートが評価時に `ThrownError` を投げること。主経路は `normalizeManifest`
だが、型共有の 1 件は `entriesType` を直接評価する）・TC-311ca3b2-d6d1-4712-9e2a-9027941d3527（private helper を単体で
叩いてパス脱出判定の深さ 0 境界を内側・外側の対で見ること）で緩和する。前者はエラーの到達性、
後者は判定ロジック単体という軸の違いで 2 つの TC に分ける。
