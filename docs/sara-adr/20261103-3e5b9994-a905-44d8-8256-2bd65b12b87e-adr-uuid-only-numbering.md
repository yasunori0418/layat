# SDR-3e5b9994-a905-44d8-8256-2bd65b12b87e: ADR は UUID だけで採番する

- ステータス: 採用
- 日付: 2026-11-04
- 関連: GitHub Issue #558, #492, `docs/adr/README.md`
- 起点: Issue #558 の分解（job adr-finish・2026-11-03）で確定。SDR-e093c6b2-75fd-4c91-a8f0-5a89e005e4ed を書き直した

## 背景

連番で採番していた旧 ADR は、UUID で採番する新 ADR と並べて `legacy_adr` 型に凍結していた。
旧 ADR の決定は 1 決定 1 ADR の新 ADR へすべて移り、旧 ADR は全部 `廃止` になった。
docs/adr の外の参照も新 ADR の ID へ付け替え終えている。

凍結した型を残すと、`docs/model.yaml` の型と relation（`revises` / `is_revised_by`）、`sara-new` の
拒否の分岐、確認用スクリプトの型の列挙に、新しく起こさない型のための記述が残り続ける。

## 決定

ADR（`adr` と `sara_adr`）は UUID だけで採番する。連番の旧 ADR は削除し、`legacy_adr` 型と
`revises` / `is_revised_by` relation は持たない。

旧 ADR の番号は、新 ADR の `origin` と本文の「起点:」行に来歴の文字列として残す。
番号から本文を読みたいときは git の履歴で辿る。

## 根拠

旧 ADR の決定はすべて後継の新 ADR が持つので、旧 ADR を残しても決定の所在は増えない。
型を 1 つ減らせば、ADR の採番の規則が「UUID で採番する」の 1 本になる。

来歴は `origin` と「起点:」行に残るので、旧番号から後継を探す手段は失われない。

## 棄却した代替案

### 旧 ADR を `廃止` のまま `legacy_adr` 型で残す

当時の本文をその場で読めるが、新しく起こさない型のための記述が model・起票ラッパー・テストに残る。
本文は git の履歴で読めるので採らない。

### 旧 ADR に UUID を振り直して残す

番号と UUID の読み替えを恒久的に持つことになる。来歴は `origin` で足りるので採らない。
