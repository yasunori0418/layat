# RISK-88088f4c-348f-4fa5-a2c1-dc42bb328b5d: 生成器の選択で優先順位を取り違える、または --manifest 経路が環境変数・設定ファイルに汚染される

## リスク

生成器はフラグ・環境変数・プロジェクト設定・ユーザー設定・既定の 5 段で解決する。段の数だけ
取り違えの余地があり、次の軸で壊れる。

- **優先順位の逆転** — 下の段が上の段に勝つ、あるいは値の決まった段より下の設定ファイルまで
  読んで、無関係な設定ファイルの不正で止まる
- **「指定なし」の扱い** — 空の環境変数や `generator` キーの無い設定ファイルを不正として止める、
  逆に未知の値を「指定なし」として黙って既定へ落とす
- **`--manifest` 経路の汚染** — activation（HM 等）の `apply --manifest` が環境変数・cwd の
  設定ファイルを読み、利用者の手元の設定や activation 実行時の cwd 次第で失敗する
- **入力不正の分類** — 未知の値・不正な設定ファイル・フラグの組み合わせ不正が `E_INPUT` に
  ならず、汎用の失敗や生成器の失敗に紛れる

## 影響

`--manifest` 経路の汚染は home-manager の switch を、配置と無関係な設定ファイルの存在だけで
止める。activation の環境は利用者の制御外なので、原因に辿り着きにくい。impact を high とする
のはこのため。優先順位の取り違えは、2 つ目の生成器が現れた段階で意図と違う生成器での配置に
なる。likelihood を medium とするのは、段ごとの「指定なし」の条件と `--manifest` の例外が
解決関数と配線の 2 箇所に分かれ、片方の変更でずれうるため。
