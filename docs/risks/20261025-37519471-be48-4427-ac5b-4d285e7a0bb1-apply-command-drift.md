# RISK-37519471-be48-4427-ac5b-4d285e7a0bb1: 事前展開した apply コマンドが意図と違う config の集合や root を配置する

## リスク

`mkApplyCommand` の文字列は評価時に固まり、devShell の入室やモジュールの activation のたびに
そのまま実行される。組み立てがずれると、実行のたびに同じ誤りを繰り返す。

- **root フラグの取り違え** — `root = "project"` が `--project-root` にならず bare `--all` に
  なると、home mode の config まで `$HOME` に置かれる
- **config の取りこぼし・選別の二重化** — `--manifest` が全 config を並べず、Nix 側で rootKind を
  見て間引くと、CLI のフィルタと判定が食い違う
- **語の分割** — `<name>=<farm>` を引用しないと、空白を含む名前で引数が割れる
- **project rootKind の prebuilt 経路** — `--manifest` で渡した project の link-farm が git
  toplevel ではない場所へ置かれる

## 影響

impact を high とするのは、誤った root への配置が利用者の `$HOME` や repo に実ファイルを
作り、devShell の入室だけで気付かないうちに起きるため。likelihood を medium とするのは、
root の enum と kick.nix の共用で分岐が増え、project rootKind の `--manifest` 経路を
これまでどのテストも通していなかったため。
