# manifest_test.go — v1 の復元と版の境界・未知フィールド・root 種別の拒否・既知値の確認

## 対象

`internal/manifest/manifest_test.go`（対象は `internal/manifest/manifest.go` の読み取りと検証）

## 検証内容

- v1 の文書の全フィールド（配置元の種別・配置元・部分パス・配置先・配置方式・root の種別）が
  定義どおりに読み取れること
- 消費側が知らない版を拒否し、しかも判別可能な値を包んで返すこと。呼び出し側が「pin した
  flake と CLI の版がずれている」という案内を出せることが契約であり、テストは包まれた値を
  判別できることまで確かめる。拒否の細目は文書の版と受け付ける上限だけを書き、対応していない
  ことは包まれた値の文に任せることも確かめる
- 版の下限をまたいで受理と拒否が切り替わること。無効側（0 および負値）は拒否し、有効側の
  境界（下限そのもの）は受理する。拒否のときは版ずれの値では包まないことも確かめる。破損した
  文書に対して呼び出し側が版ずれの案内を出さないことが契約であり、テストは包まれていない
  ことまで見る
- 未知のキーを利用者に知らせずに無視せず、拒否すること
- 評価時に絶対パスが決まる root の種別がパスを持つこと
- パスの併記が許されるのが評価時に絶対パスが決まる種別だけであること。root の種別とパスの
  有無を掛け合わせた表で、実行時に解決する 3 種（project / home / system）はパス併記を拒否し
  パス省略は受理する、評価時に決まる種別はどちらの綴りも受理する、までを確かめる。片側だけを
  見ていると、確認が種別だけを見てパスの有無を落とす方向へ縮んでも通ってしまう。受理する側の
  行はいずれも、その文書が最後まで通ることではなく、この層が判断しない事柄を表す。パスを省いた
  評価時決定の種別は engine の root 解決が、未実装の種別は engine と評価側の双方が別に弾く
- root の種別が空である文書を拒否すること。root オブジェクトを省いた書き方も、既定値を経て
  同じ確認に行き着くことを確かめる
- 配置元の種別（store / outOfStore / rootRelative）・配置方式（symlink / copy）・root の種別
  （project / home / system / fixed）が既知の値なら受理し、未知の値はどの欄であっても拒否する
  こと。拒否のときはエラーの本文に欄の名前と未知の値が載ることまで見る
- 文書が存在しないときに失敗すること
- トップレベルの任意フィールド `identity` があればその値を、無ければ空として読むこと

版と root の種別の拒否については、エラーの本文が意図した確認の由来であることまで見る。別の
確認や復元の失敗でエラーになっても通ってしまうと、確認が消えたことを取り逃がすため。未知の
キーと文書の不在の拒否は、失敗すること自体しか見ていない。

一時ディレクトリへ文書を直接書き出す fixture 方式で、nix も外部プロセスも起動しない。
