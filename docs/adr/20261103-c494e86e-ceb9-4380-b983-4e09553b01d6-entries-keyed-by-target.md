# ADR-c494e86e-ceb9-4380-b983-4e09553b01d6: entries を target をキーにした attrset にする

- ステータス: 採用
- 日付: 2026-11-03
- 関連: ADR-ee31b8d0-f7c5-442f-ae90-dcd1dd16b7a0, ADR-b06dd8ab-317e-41ee-9c80-dd70dcd7f2fd, `docs/spec.md`, `docs/design.md`, UBQ-5caf1573-b91f-40dd-a414-58b5f49bf0d9, UBQ-575f2527-64a9-4f8b-ae68-1131b053cf66
- 起点: 参照: home-manager `modules/lib/file-type.nix`（`home.file` の識別子モデル）。ADR-0014 §1・§2a・§5 を書き直した

## 背景

entries は `name` / `src` / `subpath` / `target` を持つ要素のリストで、`name` は手で付ける必須の
フィールドだった。利用者は entry ごとに論理名を考え、その一意性を頭で管理し、重複は評価時の
`throwIf` で止めていた。`name` の役割は実際には古くなった配置の除去で使う比較のキーと表示ラベルだけだった。

home-manager の `home.file` は `attrsOf (submodule …)` で、属性キーが識別子になり、`target` は
キーから既定値を取る。一方、layat の target は本来一意でなければならない値で、2 つの entry が
同じ target に置けば衝突する。

## 決定

entries を `attrsOf (submodule …)` にし、属性キーを root 相対の target とする。`target` は省略
すれば属性キーになり、明示して上書きもできる。`name` フィールドは持たず、キーの一意性は Nix の
attrset に任せる。動的な生成は `listToAttrs` などで attrset を組む。フィールドの集合と既定値は
REQ-a33a11e3-830d-4142-88ed-4c1fc35e7f74、識別子と一意性は
REQ-cb77ea05-bab8-4ccf-b09e-d23d8f71cdc7 に置く。

## 根拠

論理名を考える手間と、その一意性を管理する手間が同時に消える。attrset はキーの重複を許さないので、
一意性を確かめるコードを持たずに済む。target は配置先として元々一意であるべき値で、識別子として
過不足が無い。並べ替えで名前が変わる心配も、順序に依らない target をキーにすれば起きない。
実証済みの `home.file` と同じ形なので、利用者のすでに知っている使い方と同じになる。別のキーから `target` を
上書きして同じ target を指す衝突だけは attrset で防げず、
ADR-ee31b8d0-f7c5-442f-ae90-dcd1dd16b7a0 が評価時に検出する。

## 棄却した代替案

### `name` を任意にし、省略時は target を既定にする（リストのまま）

変更は最小だが、リストと attrset で識別子の形が揃わず、一意性の `throwIf` も残る。

### キーを論理名にし、`target` を必須にする

短いラベルは保てるが、target を書かずに済ませるという主目的を果たせない。キーで `target` を
上書きする書き方で、採った形の中に含められる。

### `name` を廃し、リストのまま target を識別子にする

attrset による一意性の保証が得られず、結局 `throwIf` か engine での検出が要る。
