# TC-b4a365cd-0b1c-40ff-92c6-91f6cffe8e98: stdout を機械可読出力が専有し人間向けの出力が stderr に留まる

## 条件

どの出力がどのストリームへ出るかを、既定の契約と `--json` の契約の双方で確かめる。

- **既定の契約** — 計画の提示は stdout、配置結果のレポートは stderr。同じコマンドの中で
  役割の違う 2 種類の出力が同じストリームに含まれない
- **`--json` の契約** — 行指向の出力が全て止まり、stdout には JSON 文書 1 つと改行だけが
  残る。止める対象はコマンド横断であり、計画・世代一覧・パス列挙のいずれも例外にしない
- **stderr の通知は両契約で維持される** — 機械可読出力を選んだからといって、人間向けの
  通知まで消えない

成功時のデフォルト沈黙も確かめる。何も変わらなかった実行を no-op として報告する一方、退避が
起きただけの実行を no-op と誤って報告しない。`--version` のようにそれ自体が stdout へ出す
ことを目的とするコマンドは、既定の書式どおりに出力する。

コマンドを足したときの配線の張り忘れを検出するため、登録されている実行系サブコマンドが漏れなく
機械可読出力の開始と公開に配線されていることを確かめる。

> 配線そのものの網羅は [エンベロープが全形状で outturn 適合を保ち subject 件数で形が揺れない](envelope-shape-conformance.md) の担当で、ここではその配線が stdout の所有権へ及ぼす
> 影響を見る。

撤去系と世代を戻す実行についても、実コマンドの処理を通した機械可読出力を E2E で確かめる
（→ issue #285）。両者は実 nix を要するため、隔離環境で実際に配置・世代を作ってから
撤去・復帰を実行し、stdout に残った文書だけを検証対象とする。
